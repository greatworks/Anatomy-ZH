# Anatomy - 深度剖析.交互式结构图解（官方中文版）

> 本技能是开源项目 [Anatomy](https://github.com/wheresryan22/anatomy)（MIT 许可，© 2026 Ryan）的中文版封装，全部功能与原版一致：SKILL.md 与 references/ 下的文档已译为中文，kit/、kit-react/、scripts/、examples-*/ 下的代码与资源保持原样。

本技能做出的图如同工作台上的一台小型仪器：带蹄脚的厚重底座、带刻度标尺的导轨、衬套上的滑架、滚花旋钮、螺旋弹簧、指针会转动的刻度盘、做成细小圆点的螺钉。读者之所以读懂了这个概念，是因为他们认出了这台机器。图上出现的每一个数字，都来自驱动其零件运动的同一个模型。

技能自带八个完整示例。动手前先打开最接近的一个。每个无框架示例都用 `node examples-<名称>/build.mjs` 构建，会在脚本旁写出一个独立 HTML 页面；加 `--light` 输出浅色主题。

为控制包体，`examples-dial-indicator/` 与 `examples-desk-computer/` 随附已构建的成品页（深色+浅色）；其余示例仅随附源码，成品页用上述命令一键重建（数秒），需要时先构建再打开。

- `examples-dial-indicator/` 是最小的示例：一台装在支架上的刻度盘，总共约 300 行。
- `examples-desk-computer/` 是无框架 SVG：一台可以敲键盘的桌上电脑。敲入的字符显示在机壳正面平面内绘制的 CRT 屏幕上，关机时整个画面收缩成一条线和一个点。约 85 个实体、850 条路径。
- `examples-arcade-cabinet/` 是一台侧板卸下的立式街机，约 240 个实体、15 根线缆的 Hero 级作品。一枚硬币飞入投币口，以圆盘在 30° 坡面上滚动能达到的速度滚下币道，触发币开关线丝后落入钱箱；开关的脉冲沿线缆逐节传到主板；CRT 预热、自检，并在倾斜监视器的平面内运行 attract mode。摇杆倾斜并合上面板下的微动开关。它展示了：如何布置相机使剖面图的机构始终可见、沿任意轴绘制的凹面电路板（棱柱）、如何用构建脚本同一个模块在页面里重建运动零件、以及如何把活的硬币与线丝画进已定序的预留槽位。`node build.mjs --audit` 可证明几何正确性。
- `examples-raptor-engine/` 是一台悬在试车台上的火箭发动机。圆形零件来自 `kit/lathe.mjs`，管路与线束来自 `kit/tube.mjs`。它可分解为 11 个组件，带交错弹簧与逐帧深度重排。每个零件都记录真实形状，`node build.mjs --audit`（`kit/audit.mjs`）可证明：静止时、分解时以及 explode 每一回放帧中，没有任何东西穿模、每个端头都落在真实安装座上、没有弯折挤压或搭在别的线上、曲面轮廓的斜率不抖动、每一处重叠都按深度顺序绘制。WebGL 的尾焰、激波、水花与蒸汽渲染在前后两层 SVG 之间。它是密集管路、平滑明暗与淡入淡出的标杆。
- `examples-ripple-tank/` 是一台高脚架上的教学 ripple tank，俯视 44°。两层 WebGL（灯光、纸面阴影与焦散，以及水面的反射与玻璃）都注册到等轴测平面，由一个纯粹的色散与光学模型（`model.mjs`）驱动；频率变化通过历史纹理从振源向外扩散。
- `examples-test-rig/` 是真实站点上的生产级图（React/Next）：弹簧滑架上的玻璃按钮、在导轨上压拉的指针探针、读取形变量的刻度盘。53 个实体、约 470 条路径。
- `examples-spot-plate/` 是同站点的第二张生产级图：点滴板上的六对玻璃液滴，每对由一个距离场绘制，距离小于 `merge` 的一对会融合成一整块玻璃。一排感触拨片设定 `merge`，每个间隙一片。它是形状互相融合、以及一个控制器驱动多个零件的标杆。
- `examples-turning-dial/` 是可选的 3D 模式：一只带机械小手的密码拨盘，真实 3D 旋转。约 90 个金属材质的活动零件、第二个旋转组、一个铰链、一根三节手指会抬起，还有一个能作为自由刚体断裂脱落的小舱。WebGL 的 LED、光池与火花跟随运动零件。旁边的 `stress.mjs` 是一只约 380 个零件、杂乱车间里的密集机械手，用于性能测试。

试验台是绘图本身的质量标杆。Raptor 是着色器工作的标杆：WebGL 效果必须达到它的世界空间、无跳变、无缝渲染标准。

## 最重要的一个理念

**物体即解释。** 不要画方块、箭头和标签。发明一件真实的、制作精良的物件，让它本身的工作方式*就是*这个概念。此前的图是这样对应的：

| 概念 | 物体 |
|---|---|
| 一个共享 GPU 上下文服务多个画布 | 一台龙门绘图机：一个打印头依次造访 16 个孔槽 |
| 缓存键在无变化时跳过重算 | 一个弹子锁：所有弹子对齐时锁芯转动，无需重画 |
| 七个每纹素字节数不同的渲染目标 | 一只七斗柜，每个抽屉的深度就是它的字节数 |
| 可分离模糊（49×49 采样 vs 49+49） | 一枚钉床印章，旁边是两个导轨上的梳子 |
| 一根会压下又会倾斜的弹簧 | 一台带弹簧、探针与刻度盘的试验台 |
| 高度轮廓 | 一个贴边按压的轮廓（形）规 |
| 依赖朝向的光照 | 一间小型照相棚：转台四周的主灯与补光灯 |

两种典型的失败方式（都真实出现过）：

- **过于抽象。** 叠放的板子、漂浮的方块、贴标签的盒子，读不出任何东西。
- **过于平淡。** 一大块平面加几条线，没有体积、没有零件、没有可发现的东西。

两者的解法相同：一台可辨识的机器，由许多细小、精密、有目的的零件构成。

**每一件作品都必须是高度精细的。** 无论概念或请求多小都适用：一个快速的解释图也仍然是一台密集的真实机器，绝不是几块板子。随规模（工作流第 1 步）调整的是推进的深度：Figure 对主体与机构做 4× 扫查，Hero 或 Epic 则覆盖整幅图。
- **读透真实物件。** 按真实物件的制造方式建造：每一颗螺钉、接缝、倒角、衬套、铭牌、带接头的线缆、带刻度的标尺，以及固定零件的那些零件。
- **两种观感。** 1× 下读作一台清晰的机器；4× 下每个区域仍有真实可发现之物——光秃的面或空荡的角落是未完成的工作，不是留白。
- **有目的，绝非噪音。** 细节来自属于机构的零件。每个零件都坐在另一个零件上、终止于一条边、淡出而非戛然而止。
- **最后检查。** 收尾前，放大到 4×（Figure 看主体与机构，Hero/Epic 看整幅图），在平淡的区域补上缺失的真实零件。

## 工作流

按此顺序推进。先写概念与零件清单，再动几何。大部分质量在此时已经决定。

1. **先定规模。** 在任何工作之前先定级，并在下档需要时告知用户大致耗时。
   - **Figure**：单个机构，40–80 个零件，至多一层 WebGL 的 SVG。定级后直接构建，不必询问。不要向用户报时，因为 Figure 通常远不到一小时就能完成；下文进度检查按至多一小时做预算。
   - **Hero**：密集物体、多层 WebGL 或一个 3D 主体，80–150 个零件。约 2–4 小时。说明后再构建，除非用户要求快。
   - **Epic**：整台载具、建筑或工厂，含多个运动系统，或 3D 模式用于多个主体。6 小时以上。不要开始。给出估算，提出一个保留核心理念的 Hero 版本，并列出完整版还会加什么。仅当用户选择时才构建 Epic。
   - 无论规模，第一个小时内必须有一个能在浏览器打开的工作页面，然后逐步加深。开始与每一步都运行 `date`；某一步超出其预估份额两倍时，告诉用户当前位置与剩余工作。
2. **真实先行。** 收集被解释事物的真实数值与行为：尺寸、数量、阈值、曲线。读数、运动与说明文字都必须为真。可以的话，把模型写成一个小型纯模块，如试验台示例中的 `rig.ts`，一切由它驱动。
3. **发明物体。** 选一台机器、工具、仪器或家具，让其机构与概念一一对应。用一句话说清什么在动、这个运动意味着什么。绝不临摹参考图：取其质感，不取其物体。
4. **零件清单。** 至少写 40 个零件（Figure 40–80，Hero 80–150，Epic 更多），分组：基座（板、蹄脚、凹槽、角螺钉、铭牌、标尺条）、结构（立柱、导轨、框架杆、限位块）、机构（滑架、衬套、弹簧、柱塞、指针）、控制（滚花旋钮、拇指螺钉、表冠）与主体本身——唯一被 lit 点亮的零件。每个零件坐在另一个零件上。`references/craft.md` 有带配方的零件词汇表。
5. **规划世界。** 世界单位约取真实事物的 1 px：x、y 在地面，z 向上。平面图用圆角矩形 `{x, y, w, d, r}` 与圆布置。选相机：默认方位角 45°，展示长边时 35–60°，仰角 30°（需要看向敞开物内部时取更高，如 ripple tank 的 44°）。然后用 `fitProjection(points, width, height, { pad, azimuth })` 适配。
6. **几何只建一次。** 用工具库在几何模块里预计算每条静态路径：`slabOf`、`cylinder`、`extrude`、`planOutline`、`topTicks`、`knurl`、`coil`、`radialTicks` 等。任意轴上的圆形零件（钟口、法兰、阀门、作动器）来自 `kit/lathe.mjs`，管路与线缆来自 `kit/tube.mjs`。运动零件在静止位建一次，用 `translateAlong` 移动。只有形状随帧变化的零件才逐帧重建。
7. **由后向前、由下向上绘制。** 重复零件用 `depthOf` 排序。任何包裹另一个零件的物体都拆成后半与前半：绕杆的弹簧、绕滑架的框架杆。运动零件画在它物理所在的槽位。参见 `references/craft.md` 的"画家顺序"。一旦图里有管路、线缆与圆形零件，就停止凭眼睛调键序：把每件物品的形状随绘制记入 `A.recorder(P, { order, spring })`，让 `A.settle(R, P)` 在两两重叠处测量真实深度并设定键序，构建收尾用 `A.auditOrExit(R, P)`。先走线再画管：两端都是真实端口、管段沿结构、交叉落在直段上、法兰处留缝（`references/craft.md` 第 8 节）。为画出的东西记录真实形状：能让审计沉默的替身形状就是 bug，审计会判它失败。滑出油封的杆是 `G.rodOut` 的一根杆，用 `A.slide` 记录。
8. **加框。** 把图放进卡片：左上 `Fig n`、右上短标题、左下交互提示、右下实时读数。图例键与真实说明放在卡片下方；除至多一个微型蚀刻标签外，字不落在画面上。
9. **让它活起来。** 用从容的基于时间的运动：指数跟随或真实弹簧。无人打扰时播放空闲巡游。图响应指针与键盘、离开视口时停止、减弱动态下静止。把属性写在 refs 上，不要逐帧重渲染。参见 `references/motion.md`。
10. **像评论家一样验收。** 物主靠放大找毛病，所以你要先放大。读一遍你做出的每一张 PNG。
    - 用 `scripts/capture.mjs` 截取桌面、手机（390 宽）、悬停与运动的若干时刻；序列、分解姿态与 `--no-webgl` 回退用 `scripts/drive.mjs`。
    - **审计跑到零。** 有管路、线缆或圆形零件时，`node build.mjs --audit` 必须以 `audit passed` 结束，每个失败项都为 0：静止、分解与飞行中的间隙、终端、松散端、弯折、自重叠、拥挤（含细长实体）、替身形状、支撑、摆动、鞍座与深度顺序。交错锁死要在几何里修，绝不用键序偏置。
    - **线条检查跑到零。** 审计看不见线条标记。`node scripts/lines.mjs page.html --out shots/lines.png`（以及 `-light` 页面、每个静止姿态下用 `drive.mjs` 的 `["lines"]` 动作）必须打印 `line ends: 0`：每条接缝、标线、筋、刻度与指针都终止在笔画、圆点或轮廓上。读那张圈出失败的 PNG。
    - **两种主题下每个接头的 4× 特写**（也要构建 `--light`），含组装态与分解态：每个法兰、三通、弯头、卡箍、阀门、波纹管、箍带、鞍座、球头与交叉，每个曲面体（不得有色调阶梯），每处纹理的终点（在边上或淡出），带接缝的平面方盒面，带编纹的软管在每个分节接头处，每根滑杆在静止位与全行程处，以及每个含文字或着色器内容的窗口。
    - **着色器：** 用 `["slow", 0.05]` 慢放每个过渡的连拍表；不得有跳变、不得有色换、边缘读数为 0。浅色主题下还要逐帧记录墨量（必须随光照单调变化），并在墨遇到笔画处裁 8–16× 放大（`references/verify.md`，"浅色主题着色器"）。
    - 把 PNG 放在示例旁问自己：它一眼就是真实物件吗？小零件丰富有体积吗？每条线都终止在什么上吗？1× 高度精细、4× 仍有可赏之处，没有光秃的面或空荡的角落吗？迭代到"是"为止。检查清单：`references/verify.md`。

## 工具库配置

工具库在 `kit/`：

| 文件 | 用途 |
|---|---|
| `kit/iso-kit.ts` | 单文件完整核心：相机、实体、零件库、SVG 字符串渲染器、卡片与页面构建器，以及 CSS（`ISO_CSS`）。拷进 TypeScript 项目即可用。 |
| `kit/iso-kit.mjs` | 同一核心编译成的纯 ESM 版，供 Node 脚本使用。直接 import。 |
| `kit/iso.css` | 写出来的 `ISO_CSS`。引入一次，并在包装元素或 `<body>` 上放 `class="iso"`（浅色主题加 `data-theme="light"`）。 |
| `kit-react/draw.tsx` | 服务端安全的 React 组件：`Solid`、`Line`、`Wire`、`Dots`、`FaceText`、`IsoFigure`、`Plate`。 |
| `kit-react/live.tsx` | `"use client"` 钩子：`useReadout`、`useLoop`、`useEased`、`useInView`、`useStillness`，外加 `spring` 与 `follow`。 |
| `kit/lathe.mjs` | 任意轴上的圆形零件：`frameAlong`、`lathe`（含光滑节点的轮廓自动开启平滑明暗）、`solidOf`、`disc`、`ringBand`、`sphereOf`、`saddleOf`、`bandsOf`（一个曲面体切成可深度排序、共享一个曲面的条带，外轮廓由 `sidesOf` 给出）、可见圆弧、圆面上的筋与螺栓圆（`ribsOf` 与 `dotsOf` 接受 `fade`，`ribsOf` 还接受 `seams`）、`rodOut` 画滑出油封的杆、`fillet` 走管线路由。 |
| `kit/tube.mjs` | `tubePieces` 把 3D 管路或线缆切成可深度排序的段（带 `breaks`、卡箍与管夹下的 `gaps`、椭圆端盖，以及跟随每个接头截面的编织/波纹/缠绕 `rings`），`tubeSvg` 画它；`crossingsOf` 找路线穿过卡箍处，`runsOf` 给已画的走线。其 `.tb-*` 填充色在 `ISO_CSS` 中。 |

| `kit/turn.mjs`、`kit/turn-build.mjs`、`kit/turn-audit.mjs` | 可选的 3D 模式。`turn-build.mjs` 有 `turning(P, { recorder })`：组（旋转、滑动、铰链、自由）、活动层、带材质的凸体，以及 `T.build`。`turn.mjs` 是运行时：`TURN.mount`、控制器、`TURN.cover`、`TURN.poseUniforms` 与 `TURN_CSS`。`turn-audit.mjs` 有 `orbitOrExit`，对每个旋转角与运动片段跑环绕审计。`references/3d.md`。 |

选择贴合项目的路径：

- **独立 HTML、静态 SVG、博客或任何非 React 站点。** 写一个 Node 构建脚本，如 `examples-dial-indicator/build.mjs`。import `kit/iso-kit.mjs`，用 `solidSvg`、`lineSvg`、`dotsSvg`、`wireSvg`、`faceTextSvg` 拼字符串，用 `figureSvg` 与 `plateHtml` 包装，再用 `pageHtml({ script: kitScript() + live })` 写出页面；有着色器时用 `kitScript() + glScript() + live`。只要单个 `.svg` 文件就用 `figureSvg({ standalone: "dark" | "light" })`，样式内嵌。
- **React 或 Next.js。** 把 `kit/` 拷进项目（如 `components/iso/`）。几何放在纯 `.ts` 模块，静态美术用服务端组件加 `draw.tsx` 组件构建，再作为元素 props 传给唯一一个 `"use client"` 活动组件去驱动运动。`references/react.md` 讲解拆分与大页面的一个坑。

## 工艺规则（简版）

这些规则把精工细作的图与普通示意图区分开。`references/craft.md` 有完整的推理与配方。

- **实体，不要线框。** 每个零件以纸色填充并按序绘制，近处遮住远处。没有透明边，没有虚线隐藏线。
- **让工具库上明暗。** `extrude` 按朝向返回四个侧面色调加一个更亮的顶面。有高度的一律用它；`flat` 只用于地面与薄于 1 单位的镶嵌。
- **色调层级。** 基座与蹄脚用 `lo`，结构用 `mid`，主体用 `hi`。有且仅有一个强调用 `lit`（深色主题里是白，浅色主题里是黑）：读者该盯的那个零件。凹槽用 `faint`，次刻度 `lo`，主刻度 `mid`，零位 `hi`。只在颜色本身就是主体时才用彩色，如红、绿、蓝通道。
- **细小精密的细节，绝非噪音。** 倒角 0.4–1.6，凹槽距边 3–5，螺钉是 0.4–0.55 的圆点且板角带环，旋钮滚花，标尺每 4–5 单位一刻度、每 5 条加粗，铭牌带三条标线。每个细节都属于某个零件。
- **线条要有落点。** 每条线终止在某个东西上：一个面、另一条线或一个终端圆点。接头是 `Wire`，其终端圆点落在物件上。没有引线、气球、尺寸箭头或漂浮在空中的标签。
- **管与线不得穿过任何东西。** 不穿另一根管、线或实体——静止时、分解时、explode 每一帧都不穿。除线自身的连接外，与一切保持约 1.5 倍半径的间隙；线沿结构走，不横跨主体正面；法兰、箍带、波纹管、卡箍或阀门包裹处给管留缝。零件相遇要么齐平、要么相切、要么轮缘贴面，绝不埋入：法兰背面落在它的端口上（端口是曲面时垫一块鞍座 `G.saddleOf`），支管从球头三通分出，每个端头（含分解态）都收尾于法兰、接手、接头壳或终端圆点。
- **每一处交叉都按真实深度顺序绘制。** 屏幕上两物重叠处，近者画在上，由 `A.settle` 与审计证明，不靠眼睛调。线交叉落在直段上且深度上分开：弯折、端头或卡箍落在另一条线的轮廓上会被读成接头（杆、拉杆、立柱或导轨都算线：管的最后一段绝不沿其中一条在屏幕上并行），一根指向观众又折回的腿会掐成一个 V（这种端口要用弯头球留出），路线绝不在屏幕上折返。一对无法排序的物品会交错锁死，解法是开口或相切接触，绝不是偏置。
- **曲面明暗平滑，绝不成阶梯。** 把曲线节点标为光滑（`[s, r, 1]`），`lathe` 用一条同时画出轮廓的单调曲线给它上明暗；大于接管的曲面体给解析轮廓 `smooth: { slope }`，长物体用 `G.bandsOf` 切段，球用 `G.sphereOf`。色调带逐渐收细到零，不落在直切上；接缝收在轮廓之内（`inner`）。
- **纹理终止于真实边缘或淡出。** 筋、螺栓圆、标线、接缝与凹槽绝不停在表面中央，无论平面还是曲面：`ribsOf` 与 `dotsOf` 接受 `fade`（淡出的筋用 `fadedSvg` 画），筋排在接缝处收头（`ribsOf(…, { seams: true })`），盒上的焊缝或接缝包角（`k.sideSeam`，即板的 `inner`），一个面上的线从一边到另一边，风口是封闭槽，刻度挂在标尺条边缘，单条必须停住的线用 `fadeLineSvg` 渐隐，特征朝上的一排（环顶的孔）要四周可见（`all: true`）。管上的纹理（编织、波纹、缠绕）跟随截面并穿过每个分节接头：`tubePieces(…, { rings })`，绝不是沿中心线的虚线。管的高光与明暗延伸到端盖并穿过每个分节接头。只有代表印刷文字的标线、指针尾梢与指针尖可以停在光面上，标记为 `free`。
- **着色器不跳变、不截断。** 每个 uniform 都挂在带起振与衰减的包络上，相位变化由物理量驱动做交叉淡化，每一项在任何边界、画布边缘与胞噪的胞边之前归零，效果活在图自身相机的世界空间里（见下）。
- **面上的东西要合身。** 机器显示的文字按其最宽字符串适配窗口并裁进窗口；透过开口看到的内容既被自身平面也被开口裁切，并画出凹槽壁。
- **体积感。** 给东西真实厚度，让它们站在别的东西上，基座与被抬起之物下放一圈柔和光晕。
- **构图。** 图居中，约占卡片 55–65%。一组图保持统一缩放，390 px 宽下仍要可读。

## 图中的 WebGL

着色器只用于线条画不出来的东西：火焰与尾气、水与焦散、真实灯光、辉光、蒸汽。零件仍是 SVG。核心规则来自第一张着色器图——它的相位间换色看起来是硬切而非淡化：

- **三层。** 后层 SVG 放被效果覆盖之物，画布放效果（`pointer-events: none`），前层 SVG 放覆盖效果之物。零件或效果横跨两侧时，拆开。
- **世界空间，同一相机。** 每个着色器点都由 `onFloor`、`onWallX`、`onWallY` 构建，或对像素射线步进 `rayOf(vb) + t·towardViewer()`。一切按世界单位乘 `uK` 计量。贴在平面上的任何东西与该平面 SVG 线条精确对齐。
- **不跳变。** 每个 uniform 跟随带起振与衰减的包络（事件用工具库的 `burst`，电平用 `settle`）。相位变化做交叉淡化，颜色随物理量连续偏移；淡出只允许变更暗。
- **无硬截断。** 每一项在任何 `if`、边界、画布边缘以及胞噪的胞边之前归零。
- **透过开口看，双重遮罩。** 窗口或凹槽后的内容在自身平面与面平面的开口都被遮罩，相乘（`references/webgl.md` 第 5 节）。
- **混合。** 用 `tonemap()` 与抖动。深色主题里，只加光的画布用预乘输出加 `mix-blend-mode: screen`；同时还需要压暗的（如 ripple tank 的水面）保持普通混合。
- **浅色主题要交付，其着色器为纸面设计。** 用普通预乘 alpha，绝不用 screen。写出纸面应呈现的颜色，再反解墨量。辉光是带浅亮核、彩色边缘与 alpha 底值的饱和体，绝不是压暗的深色主题色——那正是 Raptor 的"红墨烟雾"。
  - 光照到的东西着色，容纳它的腔体给更深的物理底色（煤灰、耐火材、水深）。
  - 高温体遵循与回退共用的黑体墨量表。
  - 墨只随光增长：淡出时一次淡掉成品墨，绝不逐项淡。
  - 墨终止于每条笔画的内缘。
  - 逐帧测墨量。`references/webgl.md` 第 8 节有配方与评审发现的故障。
- **克制。** 设备像素比封顶 1.5，只在效果活动且在视口内时渲染。减弱动态给一帧静止图，且去掉 WebGL 后 SVG 仍要可读。

写任何着色器前先读 `references/webgl.md`。

## 3D：会转的图（beta）

3D 是和 WebGL 并列的可选项。当"零件在深度中运动"本身就是概念时用它：转动的拨盘或转台、屈伸的手指、断裂脱落飞出的部件。图的其余部分保持静态工具库美术。

它处于 beta：引擎在其示例与一个测试图上得到证明，尚未用于生产图。一次只转一个主体，周围杂物保持静态。小图可跑 60 fps；一台 380 零件密集弯曲的手在 1440 下实测约 20 fps，手机档（390 px、4× CPU 降频）重载机器上 13–15 fps。

- **活动零件就是工具库自己的画面。** 每帧，凸体图元（棱柱、圆体、穹顶、带平面的球、车削体、管）由工具库规则重新投影与上明暗。转 θ 角就是工具库以方位角 `a − θ` 绘制。
- **顺序来自分离平面。** 同组两物取组内固定的平面，不同连杆上的两物取其共同坐标系里固定的平面，其余每帧求解。审计证明任何角度、任何片段帧中无环。
- **接触要么齐平、要么相切、要么轮缘贴平面。** 关节是子组上接触父连杆的同轴关节盘，否则审计判整个子组松动。没有活线跨两个运动组：线缆穿过接头两侧的线夹，或经轮毂上的滑环到达转台。
- **活动管路在近水平面或接头内部弯曲，绝不指向视线。** 一个弯需要 R ≥ 2r / sin²(e − θmax)，其中 θmax 含它经过的每个铰链的俯仰范围：平面时下界 8r，±12° 铰链上是 21r。每条路线从安装面到安装面，端口放在 `gaps` 里。这在任何角度、任何姿态下都成立。
- **材质重映射明暗坡。** 金、铬、钢、炮铜、橡胶、黄铜、铜各有明暗两组；色调仍来自朝向。
- **自由组断裂脱落不跳变。** 同轴零件是带旋转纹理的定帧画面。
- **着色器跟随运动。** 用 `controller.anchor` 或 `toGroup` 锚定到组，前层画布用 `coverOf` 遮挡，世界效果（烟、落火花、工作台上的油）留在组空间之外。
- **用 `--audit` 验收**（`turn audit passed`）与 `scripts/turn-check.mjs`（`--fidelity`、`--order`、`--pops`、`--lines`、`--perf`）。用 `--quick --only=…` 迭代。只有全量跑才证明这张图，30 个零件要 15–20 分钟，放后台跑。

先读 `references/3d.md`。
