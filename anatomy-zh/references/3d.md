# 3D：在绘图中旋转的零件

可选的 3D 模式（“旋转（turn）组”）让图（图示）的某些零件作为刚体运动：旋转的表盘或转台、弯曲的手指、断裂并翻滚的碎块。这些零件每帧都由工具库（kit）自身的规则重新投影和重新着色，并以从分离平面求解出的顺序绘制。其余一切保持为普通的静态工具库美术。未选择加入的图完全不受影响。

**状态：beta。** 引擎已在 `examples-turning-dial` 和一个测试图（仅按本文档搭出的桌面风扇）上得到验证，但尚未在生产用图上得到验证。一次只旋转一个主体，杂物保持静止，并在添加零件之前对照第 15 节评估你的图。

## 1. 图何时值得用 3D

只有当运动本身就是解释时才用：数字随转动被读出的表盘、从各个角度展示物体的转台、一轮轮组、会握持或断裂的手。绝不用作装饰。只需要某个零件滑动或指针摆动的图保持 2D：`translateAlong` 加一根重画的指针更便宜，也更精确。

## 2. 模型

- **组。** 组是带姿态（pose）的刚性坐标系。种类：`turn`（绕通过 `pivot` 的竖直轴，任意角度）、`slide`（沿一个方向，`0…travel`）、`hinge`（绕通过某点的任意轴，在 `range` 范围内，单位为度）和 `free`（任意旋转加平移，由图每帧设置）。组可以嵌套：姿态相对于父级。
- **静止状态。** 每个构造函数都接受**静止时的世界坐标**（每个组值为 0，每个自由组（free group）为 `null`）。引擎会减去每个组的原点，于是录制器（`A.recorder`）、工具库和引擎共享同一个世界。
- **动态图层。** 动态图层就是舞台中的一个 `<svg class="iso-svg iso-live" data-live="name">`。动态图层与静态图层按 `T.stack([...])` 的顺序堆叠：例如 `back svg → [dial live] → back canvas → [hand live] → front canvas → front svg`。
- **恒等式。** 把组绕竖直轴转过 θ，完全等价于工具库以方位角 `a − θ` 作画，因为工具库的光锁定在相机上。所以旋转组的每一帧都是工具库在 P′(θ) 下自己的图，只是平移过；P′(θ) 下的工具库构建器就是保真度基准，每个工具库屏幕空间审计（audit）在 P′(θ) 下都原样跑得通。铰链与自由组则改为合成矩阵（正确，稍慢）。

## 3. 最小页面

`examples-turning-dial/` 是参考场景：带滚花、刻度和数字的表盘，第二个旋转组（窗口下方的示数轮），一个铰链（骑在滚花上的棘爪），约 80 个带材质零件构成的手，会抬起的三铰链手指，作为自由组断裂脱开的六角吊舱，以及 WebGL LED、光池和火花。`examples-turning-dial/stress.mjs` 是性能场景（杂乱工坊中转台上的密集手掌）；它不是审计干净的，因此请从 `build.mjs` 借鉴模式。

`build.mjs`，精简至骨架：
```js
import * as k from "../../kit/iso-kit.mjs";
import * as A from "../../kit/audit.mjs";
import { turning } from "../../kit/turn-build.mjs";
import * as TA from "../../kit/turn-audit.mjs";
import { turnScript, glScript } from "../../scripts/inline-kit.mjs";

export const P = k.fitProjection(points, W, H, { pad: 22, azimuth: 40, elevation: 31 });
export const R = A.recorder(P);
export const T = turning(P, { recorder: R });
const dial = T.group("dial", { turn: { pivot: [0, 0] } });
const lift = T.group("f2.mcp", { parent: dial, hinge: { point: C1, axis: w, range: [-22, 0] } });
const hand = T.layer("hand");
T.stack(["back", "hand", "front"]);
export const follow = (values) => ({ ...values, "f2.mcp": -22 * (values.lift ?? 0) });
export const poses = () => Array.from({ length: 720 }, (_, i) => follow({ dial: i * 0.5, lift: (i % 90) / 90 }));

T.round({ name: "dial.body", group: dial, layer: hand, F: VERT(0, 0), s0: 10, s1: 14.4, r: 50, material: "steel", details: { ribs: { s0: 10.9, s1: 13.7, count: 150, seams: true, tone: "lo" } } });
T.prism({ name: "hand.palm", group: dial, layer: hand, plan: PALM, z: 19.4, h: 8, bevel: 0.9, material: "gold" });
T.tube({ name: "cable.red", group: dial, layer: hand, route, r: 0.7, hue: "red", material: "rubber", gaps });
// … static kit art: R.put({ name, layer: "back", svg, shapes }) as usual …

const out = T.build({ statics: R.items, poses, verify: argv.includes("--verify") });
A.settle(R, P);
if (argv.includes("--audit")) {
  A.auditOrExit(R, P);
  TA.orbitOrExit(T, R, P, { sweep: { at: (x) => follow({ dial: x }), from: 0, to: 360, frame: 0.3 }, clips: [{ name: "tap", at: (t) => follow({ dial: 40 + 12 * t, lift: tapAt(t) }), from: 0, to: 4, frame: 1 / 60 }] });
}
const stage = `<div class="iso-stage iso-turn" tabindex="0" role="slider" …>${backSvg}${out.layerSvg("hand", { width: W, height: H })}${frontSvg}</div>`;
const page = k.pageHtml({ title, theme, body: k.plateHtml({ …, body: `<style>${out.css}</style>${stage}` }), script: turnScript() + LIVE });
```
`live.js`：
```js
const controller = TURN.mount(stage, DATA.turn, { follow, onHold: () => (touring = false), onFrame: () => paint() });
function tick(now) {
  …
  controller.set({ dial: angle, lift });
  frame = visible && moving ? requestAnimationFrame(tick) : 0;
}
```
循环由图自己掌控（`motion.md`）；控制器从不运行自己的 `requestAnimationFrame`。`out.css` 即 `TURN_CSS`（面色带规则、材质、色彩管件和 `.iso-turn` 堆叠）：只引入一次。

**在 React 或 Next.js 中**（`references/react.md`）：把 `turn.mjs`、`turn-build.mjs` 和 `turn-audit.mjs` 复制到工具库旁边，并重写其中的导入（`./iso-kit.mjs` → `./kit`，以此类推），`TURN_CSS` 则作为 `turn.css` 只引入一次。几何模块（服务端）运行 `turning(…)` 和 `T.build(…)`，返回舞台标记（每个动态图层各一个 `out.layerSvg(name, { width, height })`，在静态 SVG 与画布之间按堆叠顺序排列）外加图数据中的 `out.data`。客户端挂载调用 `TURN.mount(stageElement, data.turn, { follow, onHold, onFrame })`，并从自己的循环驱动 `controller.set(...)`；在 effect 的清理函数中返回 `controller.destroy`。验证构建可以把 `out.verify` 放进数据，并让挂载过程为 `turn-check --order` 赋值 `window.__isoVerify`。

## 4. 创作 API

### 场景
| 调用 | 作用 |
|---|---|
| `turning(P, { recorder, scale = 1 })` | 构建器 `T`。传入工具库录制器，使每个动态形状也被录制，以供工具库审计。 |
| `T.group(name, { parent?, turn: { pivot: [x, y] } })` | 绕通过 `pivot` 的竖直轴旋转，单位为度。 |
| `T.group(name, { parent?, slide: { direction, travel } })` | 平移，取值 `0…travel` 世界单位。 |
| `T.group(name, { parent?, hinge: { point, axis, range: [lo, hi] } })` | 绕通过 `point` 的 `axis` 旋转，取值在 `range` 范围内，单位为度。 |
| `T.group(name, { parent?, free: { origin } })` | 自由刚体（第 7 节）。取值 `{ R: [9] \| q: [x, y, z, w] \| axis, angle, t: [3], world? }`，静止时为 `null`。 |
| `T.layer(name)`、`T.stack([…])` | 动态图层，以及由后至前的动态与静态图层名称完整堆叠。 |
| `T.build({ statics, poses, verify = false, strict = true })` | 求解每一对组合，证明每个静态项的图层，打包页面数据。`poses` 是图可达的状态（列表，或返回列表的函数）：每个运动片段（clip）都经过采样。任何找不到分离平面的组合、任何无法证明的静态项、任何非凸体零件，都会抛出可读的错误。`strict: false` 会保留互锁的组合（使植入的故障能进入审计）。 |

`T.build` 返回 `out = { svg, data, css, report, layerSvg(name, { width, height }), verify }`。`out.data` 传给页面（`DATA.turn`）。`out.report` 包含 `parts`、`layers`（每个图层：`planar`、`framed`、`dynamic`、`skip` 计数）、`tight`、`margins`、`proofs`、`seconds`。

### 构造函数
每个构造函数的通用选项：`{ name, group, layer, tone = "hi", crease = "faint", lit = false, material, owner, details = {} }`。

| 构造函数 | 零件 |
|---|---|
| `T.prism({ plan, z, h, steps, bevel })` | 竖直的工具库平板（工具库的 `extrude` 规则）。 |
| `T.prism({ F, polygon, s0, s1, round = 0, steps = 4, bevel = 0 })` | 坐标系 `F = { o, a, u, v }` 中的凸多边形，沿 `F.a` 从 `s0` 拉伸到 `s1`，任意轴向（`prismOf` 规则）。 |
| `T.round({ F, s0, s1, r \| [r0, r1], ends = ["flat", "flat"], fixed })` | 圆柱或圆锥台；每一端为 `"flat"`、`"dome"`（半径必须与侧面相同：即胶囊体）或 `"open"`。一端穹顶一端平头即半胶囊体，任意长度都成立，甚至短于半径也行（电机上的头锥即可）。竖直组中的竖直圆体会自动变成 `fixed` 图像（`fixed: false` 可阻止）。 |
| `T.lathe({ F, profile, slope, radius })` | 一般凸光滑体（r(s) 下凹）。开销大；优先用圆体。 |
| `T.ball({ c, r, flats: [{ n, d }] })` | 球体；每个平面保持 n·(p − c) ≤ d，并把它边缘画成端盖，因此 `n` 是该平面的外法线。没有平面时它是 `fixed` 图像，且不接受 `details`。它是绘制开销最大的种类（第 15 节）。 |
| `T.tube({ route, r, chunk = 6, turn = 20, gaps, breaks, caps, rings, hue, material, bundle, owner, touch })` | 工具库 `tubePieces` 的语义，分块处理；`hue` 为 `"red" \| "green" \| "blue"`；记录 `R.route`。路径从安装座（mount）表面连到安装座表面。每端的端口、密封套或夹具是单独的零件，其 `owner` 设为该管件（tube）的名称，它沿路径的跨度写入 `gaps`。从端口外表面起始的路径会通不过工具库审计的 `terminals` 检查（见下文）。 |
| `T.fixed({ svg, anchor, shapes, hull, F })` | 任意其图像在组运动下永不改变的工具库标记，通过 `translate` 移动。 |
| `T.plane({ part, o, u, v, svg, fade = [0.04, 0.3], normal })` | 零件平面内的线条或文字标记（刻度、数字、标签牌），由单一矩阵放置，随朝向淡出。 |
| `T.billboard({ part, at, normal, svg, fade })` | 投影点处屏幕对齐的标记（着色器（shader）辉光的 SVG 回退），随朝向淡出。`svg` 以投影点为中心、用 viewBox px 而非世界单位：世界尺寸要乘 `G.scaleOf(P)`（`<circle r="${(1.1 * G.scaleOf(P)).toFixed(2)}"/>` 可填满半径 1.1 的镜片）。 |
| `T.split(part, { n, d })` | 被该平面切成的两个零件（棱柱：沿轴或横轴穿过它的任意平面；圆体：横切）。切边不描边。用它打破真正的循环。 |

### 细节（在零件的坐标系中：`s` 沿轴，`x` 与 `y` 在 `u` 和 `v` 中）
每个构造函数都有自己的坐标系，并接受自己的细节种类。其他内容会被忽略，且不发出警告。

| 构造函数 | 坐标系 `[s, x, y]` | 接受 |
|---|---|---|
| `T.round`、`T.lathe` | `F`：`s` 沿 `F.a`，`x` 沿 `F.u`，`y` 沿 `F.v` | `seams`、`ribs`、`bolts`、`dots`、`rings`、`rules` |
| `T.prism({ F, polygon })` | `F` | `dots`、`seams`、`bevel` |
| `T.prism({ plan, z, h })` | 世界：`s` 是 z，`x` 和 `y` 是世界 x 和 y | `dots`、`seams`（z 值）、`bevel` |
| 带 flats 的 `T.ball` | 原点 `c`，`a` = 第一个平面的 `n`，`u` 和 `v` 来自 `G.frameAlong(c, n)`。平面在 `s = d`，远极点在 `s = −r` | `bolts`、`dots`、`rings`、`rules` |
| 不带 flats 的 `T.ball` | 无：固定图像 | 无 |
| `T.fixed({ F })` | `F`（无 `F`：无细节） | `bolts`、`dots`、`rings`、`rules` |

穹顶形旋转体 `T.ball({ c, r: 4.5, flats: [{ n: [-1, 0, 0], d: 0 }] })`（平面朝 −x，穹顶朝 +x）上的中心点位于 `at: [-4.5, 0, 0], normal: [1, 0, 0]`：`s = −r` 是极点。`[4.5, 0, 0]` 会落到平面后方 4.5 处，也就是旋转体所安装对象的内部。棱柱面上的圆环或标尺，请用 `T.plane`。
```js
details: {
  seams: [s…],                                              // rings on rounds, ring seams on prisms
  ribs: { s0, s1, count, phase, twist, fade: [0.1, 0.55], seams: true, tone },   // knurl rows on rounds
  bolts: [{ s, r, count, phase, size: 0.5, tone: "mid", fade: [0.04, 0.42] }],   // bolt circles
  dots: [{ at: [s, x, y], normal, size, tone }],
  rings: [{ at: [s, x, y], normal, r, tone }],              // become planes
  rules: [{ points: [[s, x, y]…], tone, free }],            // become planes
  bevel: 0.4…1.6,                                           // prism cap bevel (faded slots)
}
```
每个细节都随朝向淡出：点和螺栓按 `smoothstep(0.04, 0.42, n·V)`，肋逐条，倒角线逐边，平面按组的不透明度。没有任何纹理以满强度终止。

### 运行时（`kit/turn.mjs`，由 `turnScript()` 内联）
| 调用 | 作用 |
|---|---|
| `TURN.mount(stage, data, { onHold, onFrame, follow })` | 绑定 `stage` 中每个动态图层，渲染静止姿态，安装 `window.__isoTurn`。`follow(values)` 在每次 `set` 时把图的值映射为组的值（一个输入驱动联动的组）。`onFrame(controller)` 在每次渲染后运行（在此绘制着色器）。`onHold()` 在工具调用该钩子时运行。 |
| `controller.set(values \| θ, { detail })` | 设置组的值（传数字则设置第一个旋转组），同步渲染，返回统计信息。`detail`（0…1）缩放淡出的线条、肋和点（第 15 节）。 |
| `controller.angleAt(clientX, clientY, z, group)` | 把指针表示为在高度 `z` 的平面上绕组轴点的展开角（用于拖动表盘）。 |
| `controller.pose(name)` | 组的世界姿态 `{ R, t }`。 |
| `controller.detach(name)` | 在世界坐标系中延续自由组当前姿态的 `{ world: true, R, t }` 值（无跳变）。 |
| `controller.anchor(group, restPoint, restDir?)` | 组的静止世界坐标点（及方向）现在的位置：`{ world, screen, direction }`。火花源、火焰根部、LED 位置。 |
| `controller.cover(names, options)`、`order(layer)`、`orderIndex(layer)`、`events()`、`stats()`、`frames()`、`cams()`、`scene()`、`values`、`destroy()` | 遮挡蒙版（第 12 节）、绘制顺序、顺序变化事件、`{ ms, writes, moved, forced, refined, unseparated, emitted }`。 |
| `TURN.cover(controller, names \| [names, names…], { polygons = 6, edges = 10, pad = 0.3, layers })` | 供 `coverOf` 使用的 `{ uCoverEdge, uCoverCount, dropped, parts }`。 |
| `TURN.poseUniforms(controller, group, prefix = "uGroup")` | `{ prefixX, prefixY, prefixZ, prefixT }`，使 `toGroup(p)` 给出组的**静止世界**坐标。 |
| `TURN.materials`、`TURN.materialCss()` | 材质名称；单独的材质 CSS（它已包含在 `TURN_CSS` 中）。 |
| `TURN.exact(on)` | 写入不舍入的路径坐标（6 位小数），而不是舍入到 0.01 px。环绕审计会为连续性行开启它；页面永远不需要它。 |
| `TURN.rotation(axis, degrees)`、`TURN.quat(q)`、`TURN.compose(A, B)` | 以数组表示的 3×3 旋转，用于自由姿态。 |
| `TURN.floorOf(scene, group, R)` | 旋转 `R` 下组各零件的最低 z（相对于其原点）：用于把零件平整放下。 |
| `window.__isoTurn` | `{ controller, set, get, order, events, stats, layers }`；每次调用都会让图暂停（`onHold`）。`set` 接受数字或值对象。 |

## 5. 零件种类与让它们保持真实的规则

这些是强制性的；构建与审计缺了它们就会失败。
- **只用凸体零件。** 阶梯表盘分成数层；带缺口的轮子是轮毂盘加轮缘扇区；U 形托架是三个棱柱；手掌外壳是多块平板。`T.prism` 检查它的多边形，`T.lathe` 检查它的轮廓。
- **接触必须齐平、相切，或轮缘贴平面。** 球面上的轮缘不可分离：给球加一个平面（`T.ball({ flats })`），让轮缘落在它上面。埋进宿主的凸台不允许出现在动态图层中（`separation` 会以 `interlock A × B −0.6` 失败）。
- **关节。** 两个连杆保持至少 0.2 的间距，关节由子组上的关节盘（knuckle）桥接：与铰链轴同轴，接触父连杆，齐平或相切。与其铰链同轴的盘（或任何在自身平面内旋转的平面）在铰链作用下保持不变，因此永不碰撞，且它正是工具库审计所需的接触。若子组中没有任何零件接触父级，`rigid` 会把子组的每个零件报告为 `support loose`。在关节处相接的连杆共用一个半径；穹顶中心与关节距离相同，使间隙在任意角度下保持（距关节 c 处的两个半径 r 的穹顶，在 cos(β/2) ≥ r/c 时保持分离）。轭上的耳轴：
  ```js
  T.round({ name: "yaw.arm+", group: yaw, layer, F: VERT(0, 11.7), s0: 40, s1: 61, r: 1 });
  T.round({ name: "head.can", group: tilt, layer, F: frameOf([0, 0, 56], [1, 0, 0], [0, 0, 1]), s0: -12, s1: 8, r: 9 });
  T.round({ name: "head.trunnion+", group: tilt, layer, F: frameOf([0, 9, 56], [0, 1, 0], [0, 0, 1]), s0: 0, s1: 1.7, r: 4.5 });
  ```
  `tilt` 绕通过 `[0, 0, 56]` 的 y 轴铰接。罐体到达 y = 9，臂从 y = 10.7 起，因此两连杆相距 1.7。耳轴从 9 延伸到 10.7：它坐在罐体上，端面与臂相切。若在 10.5 处收尾、与臂留 0.2 间隙，整个头部的 `rigid` 会失败。
- **任何动态线路都不得跨越两个运动组。** 跨越弯曲关节的线缆或软管，是在关节两侧分别终止于卡扣或端口的两条路径，或者在铰链轴处经旋转接头（banjo）穿过。必须从静态地面接到旋转零件的线缆，沿轴向上经轮毂处的滑环（slip ring）上去（第 11 节）。
- **管件几乎平直弯曲或在接头内弯曲。** 在自水平面朝向观众倾斜 θ 的平面内、半径为 R 的弯曲，在屏幕上是一个椭圆，其最紧半径为 R·sin²(e − θ)（世界单位；换算为 px 需 × `G.scaleOf(P)`）。屏幕上转折超过 90° 且弯曲半径小于 2r 的，`folds` 判失败；小于 r 的，`self` 判失败。因此弯曲需要满足 **R ≥ 2r / sin²(e − θmax)**，其中 θmax 是平面自身的倾角加上它所经过的每个铰链的俯仰范围（旋转组会让倾角扫过每个方位角，因此最坏情况总会到来）。当 e = 30° 时：

  | θmax | 0° | 5° | 8° | 10° | 12° | 15° | 20° |
  |---|---|---|---|---|---|---|---|
  | R ≥ | 8r | 11r | 14r | 17r | 21r | 30r | 66r |

  8r 是水平平面上界限本身的值，不是余量：取 10r。超过约 15° 之后，任何实用半径都不成立，因此应在接头内转弯（卡块、万向节、肘形球、接线盒），或让线路直行。弯曲用 `G.fillet(points, R)` 画，绝不用依赖视角的圆角。审计的 `folds` 和 `self` 在每个角度和姿态下运行。
- **管件绝不正对视线。** 在任何姿态下，管件切线的仰角都要避开 15°–45° 和 −45°–−15°（e = 30° 时的 `endon`）：在铰链链上，还要检查连杆的俯仰范围（弯曲 30° 的连杆上的线缆会失败）。
- **车削体（lathe）是唯一带有细小残余台阶的种类**（色带改变拓扑处 ≤ 2.5 tone·px²）。动态零件优先用圆体、穹顶和带平面的球。

## 6. 材质

零件的材质（material）是其构造函数上的一个选项（`material: "gold"`）。色调仍完全按工具库的方式由朝向决定；材质会重映射色阶（四种明暗、顶部、纸面、轮廓和线条色调、点与管件本体、亮部与暗部），浅色主题（light theme）和深色主题（dark theme）各有一套。

| 材质 | 观感 |
|---|---|
| `gold` | 香槟金阳极氧化铝：暖色调的浅色顶面，青铜色暗部，深青铜轮廓。 |
| `chrome` | 明亮的抛光钢：一条浅色远带，暗色反射带（n·L 0.2–0.42）紧邻亮带，外加白色高光。刻意做得非单调：色带随朝向移动，绝不跳变。 |
| `steel` | 缎钢，单调且偏冷。 |
| `gunmetal` | 深蓝灰金属，带浅色斑点。 |
| `rubber` | 黑色橡胶与线缆护套，带柔和光泽。配合 `hue`，管件变成彩色护套（色相混入橡胶色阶）。 |
| `brass`、`copper` | 用于接头、端口、阀门的暖色金属。 |

静态零件使用与普通类相同的族：把工具库标记包进 `<g data-mat="brass">…</g>`（示例中的示数楔形）。规则位于 `TURN_CSS`；只含静态美术的页面可以只引入 `TURN.materialCss()`。浅色页面中的深色底板会选择深色主题配置（`.iso[data-theme="dark"] [data-mat]` 排在最后）。

在浅色页面上，带材质的图远比工具库灰强烈：地面（工作台、底座、板）保持工具库色调，材质只给主体，这样它才像被照亮的成品物件。

## 7. 自由组：会断裂脱开的零件

`T.group("pod", { parent: dial, free: { origin } })` 创建一个刚体，其姿态由图每帧设置。静止时（`null`）它停在构建时的确切位置，附着于父级：由父级承载。要使其断裂脱开，开始设置相对于父级的姿态：不存在单帧突变，因为第一个值是单位变换。
- **落到转台上**：父组保持为转台组，让零件先落下、再随它转。飞行按时间的纯函数计算（示例中的 `breakAt(t)`：绕质心的筋斗、弹道弧线、用 `TURN.floorOf` 求得的贴合着陆、衰减的滑动与偏航）。纯函数能被构建和审计采样，也能倒放。
- **落到工作台外**：用 `controller.detach(name)` 切到世界空间，它返回延续当前姿态的 `{ world: true, R, t }`，然后从那里继续积分。
- **顺序**：自由组的零件在运行时与所在图层的每个零件配对（先按屏幕包围盒，再按相对姿态缓存 GJK 平面）；组内配对是平面的。自由零件之间原则上可能出现循环；审计会对片段采样并报出来。
- **证明**：把片段放进 `poses()` 交给构建（断裂过程在多个旋转角下的每一帧），同样的片段（`clips`）交给审计。审计在每个片段帧中摆放每个形状，并检查与动态和静态零件的间隙（`posed`）、顺序、循环和连续性。

## 8. 铰链链：手与手指

每个连杆是一个铰链组，其父级是前一个连杆（`T.group("f0.j1", { parent: f0j0, hinge: { point: J1, axis: w, range } })`）。手腕是承载手掌的铰链；拇指根部是承载拇指链的铰链（竖直轴）。通过 `follow` 用一个图的值驱动整条链（`lift` → 三个角度）。
- 不同连杆上的配对尽可能在构建时求解：一对组合在构建的 `poses()` 上扫过的体积，只要在其共同祖先的坐标系里存在裕度 ≥ 0.1 的平面，就成为 **framed** 平面（运行时不做 GJK）。只有近关节配对保持动态（GJK，热启动，两组保持相对姿态时缓存）。因此 `poses()` 必须覆盖该运动：手势一旦离开采样范围，审计的 `unseparated` 行就会点名该配对（"framed plane: … add it to poses()"）。
- 范围保持符合物理且要小：每关节 ±5° 的三连杆手指已经像在动的手；每关节 20° 则需要重新证明每条路径和每个接触。
- **铰链连杆上的路径继承该连杆的俯仰范围。** 第 5 节的 `endon` 规则及其弯曲界限都使用线路可达的倾角，而非静止时的倾角：±12° 铰链上 R = 8.6r 的水平 90° 弯曲（在平面 8r 规则之内）会失败于 `folds` 和 `self`，因为 12° 俯仰时需要 21r。让线路直入接线盒，或把弯曲移到父级。

## 9. 绘制顺序，以及它为何正确

每一对可能在屏幕上重叠的零件都会被赋予一种关系：固定在其共同组中的平面（planar）、固定在其共同祖先坐标系中的平面（framed）、每帧一个 GJK 平面（dynamic，彼此相对运动的不同组），或跳过（一条路径上相邻的块）。在该坐标系中，当 n·V > 0 时 B 在 A 前。顺序是以上一帧顺序为键的稳定 Kahn 排序；遇到停顿时，精确屏幕凸包相互分离（或在 0.1 px 内相接）的零件之间的边会被丢弃；剩余的停滞构成一次强制选择，它会被计数，并被审计判为致命。

其正确性在于：两个不相交的凸实体（solid），若投影重叠，则都会被某条视线击中，而分离平面与该视线只相交一次。无闪烁是因为：平面的关系只在平面侧立时翻转，而那时两个投影落在一条直线的两侧——交换它们不改变任何像素。侧立关系（|n·V| < 1e-7）不产生边。

## 10. 着色与淡出

- 平面（棱柱侧面、端盖、球的平面）用工具库的阈值（竖直棱柱用 `EB`，其余用 `LB`）经平滑阶梯处理：面保持工具库色调，只在阈值 ±0.035 范围内交叉淡变，每条色带分 64 步（`data-q`，0…256）。这么细的步长让铬的高对比色带保持平滑。
- **连续性行测量的是不舍入的几何。** 页面把路径坐标舍入到 0.01 px 写出，边缘最多移动 0.005 px，远小于一个设备像素。在这些舍入路径上测量，长边的舍入台阶从不缩小，于是减半测试曾把大平面（示例的手掌、桌面风扇高 21 的棱柱臂）读成并不存在的跳变。因此 `orbit` 会为连续性行把运行时切到精确坐标（`TURN.exact(true)`），之后再切回来；旋转组上的大平面没有问题。
- 曲面总是用解析等轴测光带（`labelledArcs`），绝不用小平面。胶囊穹顶是嵌套凸包；带平面的球是被裁掉的端盖。色带诞生时宽度为零。
- 淡出线条的槽位容纳肋和倒角：alpha 量化到 1/32，槽位数取构建的环绕（orbit）扫描显示一组所需的数量。
- `lit: true` 使用 lit 记号；有材质时用该材质的 lit 配置。

## 11. 静态图层与转台周围杂乱的工坊

每个静态项都带 `layer`（`R.put({ …, layer: "back" })`），构建要在所有可达状态下证明它与每个动态图层的恒定关系，用第一条成立的规则：**水平面**（该项完全在图层 z 范围之下或之上）、**圆柱规则**（该项沿视线的地面方向完全处于旋转组扫掠圆柱的后方或前方）、屏幕上**永不重叠**，或**扫掠包络面**。否则：`static S interleaves live layer Λ: split S at z = …, or move it`。

密集工坊的创作规则（`examples-turning-dial/stress.mjs` 证明了 450 种关系：工作台、转台底座、电源单元、工具架、线缆卷盘、托盘、扳手、三条工作台线缆）：
- **杂物保持在扫掠圆柱之外或转台平面之下。** 高的物件（电源单元、机架、灯）沿视线的地面方向（cos a, sin a）放在半径 R 的圆柱（动态图层离轴的触及范围）后方或前方。在它旁边、既不后也不前的物件必须矮。
- **转台最低动态 z 以下的一切都在动态图层之后，即使它在工作台上位于前方。** 它属于动态图层下面的图层（`back`），而不是 `front`：构建会如此判定。
- **必须接到旋转零件的线缆**在工作台上铺到固定底座，在底座内上行，经轮毂处的滑环或旋转接头接到旋转零件。静态段画到底座上的端口，动态线缆从旋转托盘上的接线端子板起头。任何路径都不得同时跨越静态地面和旋转组。
- 静态线缆平放在工作台上（弯曲在工作台平面内，R ≥ 8r），因此永不折叠，末端接端口、卷盘，或标 `free` 的自由端。搁在工作台上的线缆（中心在台面 + r）会碰到台面，工具库的 `clearance` 检查会判失败（`close stand.feed × stand.bench clearance 0.00 < 0.40`），除非路径自己说明：`R.route(name, route, r, { owner: name, limp: true, touch: ["stand.bench"] })`。
- `stress.mjs` 是性能和图层证明场景，不是审计干净场景：它的工作台线缆没有 `touch`，它的手有松动的连杆，因此工具库审计会判它失败。创作模式请抄 `build.mjs`。

## 12. 跟随旋转与组的着色器

`kit/gl.mjs` 增加了以下内容（两者都需显式选用；旧片段看不到任何新东西）：
- `GLSL_TURN`：`uGroupX/Y/Z/T`、`toGroup(p)`、`toWorld(g)`、`dirToGroup(d)`、`dirToWorld(d)`，以及遮挡蒙版 `uCoverEdge[60]`、`uCoverCount[6]`、`coverOf(vb, soft)`。
- `glslPose(Name, prefix = "uName")`：为任意组提供同样的四个函数（`toDial`、`fromDial`、`dirToDial`、`dirFromDial`），于是一个着色器可以跟随多个组。
- `glLayer` 把长于 4 的数组按声明类型送进 `vec2`/`vec3`/`vec4` uniform 数组（float 数组不变）。

着色器如何跟随运动：
1. **运动零件上的内容**（指尖的 LED、破裂管线末端的火焰、管口喷出的油）：每帧用 `controller.anchor(group, restPoint, restDir)` 取锚点，把 `world`、`screen`、`direction` 当 uniform 传进去。把它画在**前画布（canvas）**上（盖住动态图层），并用画在它后面的零件遮挡：`const c = TURN.cover(controller, [partName]); layer.draw({ ...c, … })`，再 `ink *= 1. - coverOf(vb, .7 * px)`。每个动态零件都是凸体，所以它的凸包就是精确轮廓；遮挡向外扩 0.3 vb，让墨迹停在遮挡物描边上，绝不进入描边内部。多个目标共用这六个多边形：`TURN.cover(controller, [["hand.f2.p3"], ["hand.pod.socket"]])`。
2. **固定在旋转表面上的内容**（转台上积的油、表盘上被光显现的纹理）：传 `TURN.poseUniforms(controller, "dial", "uDial")`，在静止世界坐标里求值：`vec3 q = toDial(onFloor(vb, FACE_Z));` 油池随表盘一起转。
3. **世界空间里的内容**（上升的烟、离开源头后的火花、转台外工作台上积的油）：绝不碰组变换。粒子在出生时从锚点的世界位置发出，在世界空间积分（示例的火花）：旋转不会拖着它们走。
4. **后画布**（光照进被零件盖住的表面）：把画布放在两个动态图层之间。示例把表盘单独拆成 `hand` 下面的动态图层 `dial`，于是 LED 的光池落在表盘面上，手盖住它完全不需要蒙版。

`webgl.md` 的每条规则依然有效：包络、在任何绑定前把窗口置 0、浅色主题墨色（饱和的本体、浅淡的核心、带色调的地面、墨色只随光增强）、抖动、画布边缘置 0、SVG 回退（`T.billboard` 放在所属零件内、藏在 `[data-gl]` 之下、用 `(1 − u)/(1 − u·α)` 交接）。遮挡块用掉 70 个 uniform 向量：读一下 `MAX_FRAGMENT_UNIFORM_VECTORS`，并让 SVG 回退控制在 128 以下。`GLSL_TURN` 已经定义了 `toWorld`：不要把它前置到自带该声明的片段前面。

## 13. 环绕审计

`node build.mjs --audit` 先跑工具库审计，再跑 `TA.orbitOrExit(T, R, P, options)`，它每项检查打印一行，以 `turn audit passed` 或 `turn audit failed: n problems` 结束（退出码 1）。只有完整运行才会以 `turn audit passed` 结束：带 `only` 的运行以 `turn audit partial: no problems in what ran (n lines skipped by only)` 结束，快速运行以 `turn audit quick: no problems in what ran (quick run, undersampled: the full run is the proof)` 结束。

选项：`sweep: { at(x), from, to, frame }`（旋转）、`clips: [{ name, at(t), from, to, frame }]`（手势、断裂分离：60 fps 逐帧）、`poses`（额外状态）、`crowd: [[route, part]…]`（豁免 `crowding` 的配对，要看过之后再定）、`cover`、`fittings: [[route, from, to]]`（接头内的路段，豁免 `endon`）、`quick`（状态数约少 10 倍，用于迭代）、`only: ["order", "rigid", "swept", "posed", "routes", "coverage", "continuity", "depth"]`（未知名称会抛错）、`log`。示例接受 `--quick`、`--only=a,b` 和 `--verbose`。`only` 运行这些行：`order` → `unseparated`、`cycles`、`forced`、`swaps`；`routes` → `folds`、`self`、`crowding`、`endon`；`depth` → `depth`、`layers`；其余各项各归各行。`separation` 始终运行。没运行的行打印 `skipped`。

**耗时与迭代方式。** 环绕审计很慢，耗时随零件数 × 状态数增长。在 28 零件的桌面风扇上实测（一个旋转、一个铰链、一个片段）：`--quick` 85 秒，完整 17 分钟。示例场景要跑几分钟；完整运行按每零件约 30–40 秒做预算。这已超过 10 分钟的 shell 超时，所以：
1. 修哪几行，就用 `--quick --only=…` 在那些行上迭代。
2. 最终运行之前先单独跑一次 `--quick`。它采样不足：完整运行检查了 800 个减半候选，它只查了 100 个，漏掉了完整运行发现的 20 个 `continuity` 失败。
3. 最终完整运行丢到后台（`node build.mjs --audit > audit.txt 2>&1 &`），结束后再读。只有那次运行的 `turn audit passed` 算数。

| 行 | 失败于 | 修复 |
|---|---|---|
| `separation` | 同组配对没有平面（裕度 < −0.08） | 拆分、加平面，或做齐平接触 |
| `unseparated` | 跨组配对在其凸包重叠时互相穿插；某状态破坏了 framed 平面 | 修接触或运动；把该运动加进 `poses()` |
| `cycles` | 某状态下重叠零件之间成环；会打印零件、状态区间和拆分平面（裕度最大的那条环边） | 就在该平面上 `T.split` 那个零件 |
| `forced` | 运行时不得不强行挑选 | 同 `cycles` |
| `swaps` | 两个重叠零件在重叠超过 0.25 px² 时交换顺序（齐平搭建、裕度不足 0.05 的配对为 0.5 px²：接触平面侧立的一瞬，真实重叠是一条线，画出来的曲线会留下约 0.1 px 宽的细缝） | 先看：`drive.mjs page.html '[["orbit", "swap.png", θ−0.3, θ+0.2, 0.1, null, 6, [x, y, w, h]]]'`（θ 取自该行；底板 CSS px 中配对周围的区域，缩放 6）。一步之内出现或消失的东西是绘图 bug，不是顺序 bug。2026-10-06 之前的引擎画一端 `"dome"` 且短于半径的圆体时，会在平端背后画一个楔形，该端一侧立就消失：复制现在的 `turn.mjs`。两侧顺序都正常（`__isoTurn.order`）的干净交换，说明平面错了：带上零件对和 θ 报告 |
| `layers` | 静态项位于动态零件的错误一侧（射线投射） | 移走或拆开它（第 11 节） |
| `rigid` | 静止下的工具库间隙、端子、支撑、实体间隙 | 同工具库审计。铰链组每个零件都 `support loose`：组里没有东西接触父级（关节盘，第 5 节）。`terminal … from X`：路径起于端口的面而不是安装座（`T.tube` 行，第 4 节）。`clearance … × stand.bench`：工作台线缆没有 `touch`（第 11 节） |
| `swept` | 旋转组扫掠包络里有静态形状 | 把它移出圆柱 |
| `posed` | 不同组的形状（以及运动的动态 × 静态）在任一采样状态下互相穿过 | 改运动或改几何 |
| `folds`、`self`、`endon` | 每个角度和摆定姿态下的动态路径 | 第 5 节（弯曲半径含俯仰范围，第 8 节） |
| `crowding` | 动态路径的末端或弯曲在某角度落在细长实体（杆、柱、梗）的轮廓上 | 与旋转杆平行的线，无论偏移多少，都会在某个角度穿过杆的轮廓，所以没法靠设计规避。看它点名的角度（`["turn", θ]` 加一张 4× 截图），如果读起来像两个独立零件，就把该配对列进 `crowd: [["cable.a", "yaw.stem"]]`，或者把线走到杆里面。线不平行时：斜穿越过该杆 |
| `coverage` | 零件记录的形状覆盖不到其绘制的 60% | 记录真实形状 |
| `depth` | 射线投射的基准答案与引擎顺序不一致 | 报告它 |
| `continuity` | 每 0.05°：色调台阶 > 1/16 条色带、新生 > 2 px²、点的 α 台阶 > 0.01、淡出 α 台阶 > 1/32 + 0.005、轮廓移动超过 1.5·ω·Δθ + 0.05 px；以及减半测试 | 收住的细节：把它淡出。轮廓或面边界一步跳变的零件：用 0.1° 的环绕表找出角度；普通工具库图元上出现它就是引擎 bug，带上零件和 θ 报告。`--quick` 采样不足：只有完整运行算数 |

减半测试用精确坐标把每个候选台阶按自身的 ½、¼、⅛ 重新发一遍，把帧按 4× 光栅化（8 条子扫描线上的抖动采样），测量易主的像素并按色调加权。平滑变化随台阶减半，跳变不会。某台阶在每次减半后仍保持在 60% 以上、且到 ⅛ 时仍 ≥ 2 tone·px²，即在 4× 下测量、再到 16× 下测量都成立时，判为不连续：4× 失败的台阶，只有 16× 也失败才算失败。若改在页面舍入过的路径上测，每条长边都有一条约等于其长度 × 0.01 px 的地板，永不下沉；切换到精确坐标之前，正是这条地板把大平面标记了出来。每一行都有一个必然使其失败的植入故障（构建会话里的 `3d/engine/plants.mjs`：一个下沉的凸台、三根斜棍组成的风车、竖直面里的纤维弯曲、30° 的管件、一排停住的肋）。

## 14. 浏览器检查

```sh
node examples-turning-dial/build.mjs --light --verify           # writes turning-dial-verify-light.html
node scripts/turn-check.mjs examples-turning-dial/build.mjs --fidelity
node scripts/turn-check.mjs page-verify.html --order --step 1
node scripts/turn-check.mjs page-verify.html --order --states clip.json
node scripts/turn-check.mjs page.html --pops --no-webgl --step 1 --out shots/pops
node scripts/turn-check.mjs page.html --lines                    # and the dark page
node scripts/turn-check.mjs page.html --perf --width 1440
node scripts/turn-check.mjs page.html --perf --width 390 --throttle 4
node scripts/turn-bench.mjs examples-turning-dial/build.mjs
node scripts/drive.mjs page.html '[["turn", 37], ["shot", "a.png"], ["orbit", "orbit.png", 0, 345, 15]]'
```
- `--fidelity`（Node）：棱柱对 `k.extrude`/`G.prismOf`（轮廓、顶面和各面分别 ≤ 0.06 px），圆体和车削体对 `G.lathe(…, smooth)`（对 10× 放大绘制的工具库，轮廓 ≤ 0.05 px、色带 ≤ 0.5 px；该行还会打印对工具库自身路径的轮廓，后者舍入到 0.1 px，所以那里 0.08–0.13 px 是预期的，不作判定），管件对 `tubePieces`（0.05 px），都在 P′(θ) 下。对照：画歪 2° 的一个棱柱必须失败。
- `--order`：把记录的形状放进 WebGL z 缓冲，对 DOM 绘制器的填充，2×；带 4+ 个内部像素的动态配对失败。对照：每个动态图层反转必须给出 ≥ 1000 px。静态 × 动态的不符会列出来（静态记录的形状常常只是替身，例如用一块平板代替带窗的板）。`--part name` 在两幅图里打印该零件的占用范围。`--step` 只扫**第一个旋转组**，其余组都保持静止：铰链、滑动或片段要用 `--states`。
- `--pops`：一阶差分（θ → θ + 0.02°，两次腐蚀）与二阶差分（0.1°，|2b − a − c| > 56，或平色像素上 > 6，一次腐蚀；6 px 的核判失败）。对照：最大的零件藏一帧。`--out dir` 保存第一个核的帧。配合 `--states` 时，相邻条目被当作相邻帧，只跑一阶差分，因此列表必须是**步长约 0.02° 的一条连续路径**：529 个互不相关的偏航 × 俯仰姿态造成了 404 个假失败；0.02°、1201 个状态的俯仰扫描得到 0 个。
- `--states file.json`：用值对象的列表代替角度。从构建模块里写出来，它导出 `follow` 和各片段函数：
  ```js
  import { writeFileSync } from "node:fs";
  import { follow, nodAt } from "./build.mjs";
  const at = (t) => follow({ yaw: 20 + 30 * t, tilt: nodAt(t) });
  writeFileSync("clip.json", JSON.stringify(Array.from({ length: 241 }, (_, i) => at(i / 60))));
  writeFileSync("tilt-path.json", JSON.stringify(Array.from({ length: 1201 }, (_, i) => follow({ yaw: 30, tilt: -12 + i * 0.02 }))));
  ```
  `clip.json`（片段在 60 fps 下的每一帧）用于 `--order`；`tilt-path.json`（一个铰链以 0.02° 扫描）用于 `--pops`。每个铰链跑一条路径的 `--pops`，旋转角选铰链零件重叠最多的那个。

## 15. 性能

由 `turn-bench`（Node CPU）和 `turn-check --perf`（浏览器，240 帧、每帧 1.1°）测量。

**一个零件花多少。** `turn-bench` 按种类打印每个零件的 Node 耗时。以棱柱为单位（一个动态棱柱，在构建机上每帧约 0.03–0.04 ms）：

| 种类 | 开销 | 种类 | 开销 |
|---|---|---|---|
| `fixed`（竖直圆体、普通球） | 0.5 | `round` | 2.5–4 |
| `prism` | 1 | 带 flats 的 `ball` | 8–10 |
| tube chunk | 2–3 | `lathe` | 约 25 |

图的权重是总和。**小图**权重至多约 50（几十个零件，以棱柱和固定图像为主）；**密集图**至多约 230。桌面风扇（28 个零件：6 个棱柱、7 个 fixed、5 个 tube chunk、8 个 round、2 个带 flats 的 ball）权重约 65，实测每帧 Node CPU 1.6–1.9 ms、1440 下浏览器任务 6.0 ms，所以它在小图线之上，主要是因为那两个球。旋转表盘（88 个零件、42 个 round、一个 lathe）权重约 225，实测 6.4–7.2 ms。带 flats 的球是有轮缘落在其上的穹顶端的正确零件（第 5 节），但它抵得上九个棱柱；普通球或竖直圆体是固定图像，几乎不花钱。耗时随机器和负载而变：在同一次运行里比较种类，并测你自己的图。

| 指标 | 小图预算（权重 ≤ 50） | 密集图预算（权重 ≤ 230） |
|---|---|---|
| 每帧 Node CPU | ≤ 2 ms | ≤ 7 ms |
| 1440、DPR 2 下的浏览器主线程任务 | ≤ 6 ms | ≤ 13 ms（60 fps） |
| 390、DPR 3、4× CPU 下的主线程 | ≤ 16 ms | ≤ 33 ms（30 fps） |
| `data.turn` JSON | | ≤ 250 KB |

可用的调节手段，按序：
1. 每个竖直轴旋转的零件、每个普通球都用 `fixed`（自动）。
2. 面上的每一组线条或文字都用平面；竖直棱柱的顶面只要一个矩阵。
3. 小零件按设备像素采样：30 px 以下小零件的环、端盖和穹顶取 12–16 个采样，绝不用大零件的最小值。
4. **framed 平面与相对姿态缓存**（自动）：两组只要保持相对姿态（纯转台旋转），跨组配对就不花成本；构建采样过运动的配对会成为 framed 平面。
5. **自适应半帧率**（图的循环）：保持 `controller.set(...)` 耗时的指数移动平均；超过 14 ms 时隔帧渲染动态图层（基于时间的运动不变），低于 9 ms 恢复每帧渲染（`stress.mjs` 的循环）。
6. **按速度给细节**（选用）：`controller.set(values, { detail })`，取 `detail = settle(1 − smoothstep(120, 240, |ω|°/s), 0.25 s)`：淡出的线、肋和点随之缩放，低于 0.01 就跳过。轮廓和色调绝不缩减。

让图留在预算内的创作规则：每个运动组约 150–250 个动态零件；小细节做成 `details`（点、环、螺栓）而不是零件；静态杂物做成静态美术；每个独立运动的区域一个动态图层；管件按 6 分块，弯曲允许的情况下块数越少越好。示例和压力场景的实测数字见技能的构建说明；本机上 380 零件会弯的手，配上半帧率手段，在 1440 下是 30 fps 的图，不是 60 fps。

## 16. 已知限制

- 竖直旋转轴走方位角捷径；其他旋转合成矩阵。
- 只有凸体零件。凹体拆成凸块；球平面代替轮缘贴球的关节。
- 动态管件遵守折叠与端视规则：没有扫掠管件的轮廓，所以转弯要么平缓、要么在接头里，且没有路径跨越两个运动组。
- 不自动拆分：循环是审计失败，并附一个建议平面。
- 平面在得分 ±0.035 的范围内交叉淡变（约 8° 的转动）。
- 车削体在色带改变拓扑的地方保留细小的残余台阶。
- 自由组在运行时与整个图层配对；几十块碎屑运动时都要花 GJK。
- 手机：预算瞄准 30 fps 而不是 60，只有预算内的图才做得到。380 零件的压力场景（`examples-turning-dial/stress.mjs`）在重载机器上、开着半帧率手段实测：1440 下约 20 fps，390 下 13–15 fps（4× CPU 降频）。没有画布绘制器。
