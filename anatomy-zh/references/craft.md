## 1. "精工"的含义

获得批准的图示有五个共同特质。

1. **一件可以真实建造的实物。** 读者一眼就能叫出它的名字：一台测试台、一个百分表、一个抽屉柜、一台龙门绘图仪、一把锁。它是为主题发明出来的，绝不是照着参考图描出来的。
2. **许多小而精确的零件。** 一个好的行内图示有 30–60 个实体和 300–500 条路径。一个零件确实更多的主角主体可以承载远多于此的数量：台式计算机约有 85 个实体，Raptor 约有 270 个实体、478 个按深度排序的条目。每个零件都架在另一个零件上，与相邻零件对齐，并且各司其职。密度来自结构（支脚、导轨、限位、衬套、旋钮），而不是来自纹理。
3. **体积感。** 零件有真实厚度，侧面以四种色调着色，顶面较亮，有能捕捉光线的倒角，下方有柔和的光晕。
4. **克制。** 细 0.6 px 的线条与收敛的调色板。唯一一处点亮的高光告诉眼睛该看哪里。运动经过缓动，且慢到可以跟上。
5. **真实。** 读数显示实时的、正确的数字，运动遵循真实模型：具有真实刚度的弹簧、真实的尺寸与阈值。

## 2. 反模式

以下每一条都被评审者否决过，所以不要这样做：

- **抽象堆叠。** 用来代表"层"的漂浮板、大板或瓷砖太抽象，读不出任何东西。如果需要表现层，就把它们做成抽屉、机架里的托盘、导柱上的板，或托架中的卡片。
- **一大块平板。** 一个大平面上只画几条线，太单调平淡。把它拆成底座、滑架和各种零件；加上凹槽、螺钉、标尺和铭牌。
- **蓝图式家具。** 引出线、带数字的气球标注、尺寸箭头、剖面线、表示隐藏边的虚线以及漂浮的标签，属于图例和说明文字，而不是图本身。
- **半途而废的线条。** 扇形指引线、差一点才连到零件的连接线，或在轮廓角之前就断掉的折缝。每条线都必须落在某个东西上。
- **线框图。** 能看到背面边线的透明盒子。
- **到处都用彩色。** 保持单色，除非彩色本身就是主题：一处点亮的高光，加上仅用于色彩通道的真 RGB。流体默认不是彩色的：视镜里的油、水箱里的水和管件里的冷却液，都是图示自身墨色的淡色调，`--no-webgl` 回退绘制与着色器相同的淡色调。一个盲测台把油涂成饱和的橙色，而图的其余部分是灰色的，它的回退油却是灰色的。
- **在图里写字。** 最多允许一个微小的蚀刻标签（面上的 `FaceText`）。其他一切都放进卡片角落、图例或说明文字。
- **照抄参考图。** 从参考图中汲取氛围和质感，然后发明出这个物体。
- **指针生硬跳变。** 零件瞬间吸附到光标。一切都加缓动。
- **管穿管。** 在第一版 Raptor 上，负责人放大后发现线缆和管线穿过主管道、彼此穿插，"这毫无道理"。在 1× 下它看起来没问题。每根管件和每根线缆除自己的连接点外，都与一切保持间隙，每个交叉都按真实深度顺序绘制，`kit/audit.mjs` 同时证明这两点（第 8 节"间隙与交叉"）。
- **突然中断的纹理。** 在同一张特写里，燃烧室上的螺栓点阵在表面中间戛然而止，钟体与喉部被画成一串平铺的色块阶梯。两者都读起来像坏了一样。负责人的原话是：如果纹理必须结束，"我们宁愿让它在末尾淡出，也不要突然停止"。曲面要平滑着色，纹理要么结束在真实的边上，要么淡出（第 8 节"曲面上的着色与纹理"）。
- **跳变或被切断的着色器。** 第一版 Raptor 的羽流在相位之间瞬间变色，"像被剪出来一样"，一处辉光在画布边缘以一条直线结束。每个着色器项都乘在一个包络上，并在任何边界之前归零（`webgl.md` 第 7 节）。
- **平面上同样突然中断的纹理。** 同样的毛病在后一个图示的箱体上复发了，而那里没有任何曲面规则能覆盖到：一个水箱的焊缝在每个圆角内缩 6 单位，一个歧管面上的分型线内缩 4，一排淡淡的刻度漂浮在裸底座板上而下方没有标尺，散热筋两端都停在离接缝弧 2 单位的地方，还有一段软管编织层被画成沿中心线的虚线，沿软管以两条笔直生硬的边结束，并在每个管段接头处断开。箱体上的接缝绕过可见的圆角、从一条边到另一条边（`k.sideSeam`），筋结束在与它相同 `s` 处的接缝上（`ribsOf(…, { seams: true })`），刻度悬挂在标尺条的边缘，管件上的纹理来自 `tubePieces(…, { rings })`。`node scripts/lines.mjs page.html` 会让每一处什么都没碰到的线端失败（`verify.md`，"Line ends"）。
- **替身形状。** 为了让审计安静下来，一个构建者在五个相互重叠的杆复制品末端各记录了一个 0.45 厚的圆盘，又给第二根画得沉入气缸头的杆记录了一个薄片。审计通过了，对两根杆什么都没说，而那根点亮的杆在移动时，轮廓每 12 单位就被啃出一个缺口。记录你画出来的东西的真实形状；审计的替身检查会让记录形状覆盖不足其绘制 60% 的条目失败。一根从密封座滑出的杆就是一根杆（第 3 节"从密封座伸出的杆"）。
- **把深色主题的辉光直接贴到白纸上。** 负责人把浅色定为每个站点图示的发布主题，七个建立在深色底板上的着色器图示不得不改造。把深色辉光再调深，得到了"红墨水烟雾"（Raptor 的浅色羽流）。它还给出了画成轮廓的火焰、看起来像污垢的火花、鲑鱼色的冷却玻璃、灰色的淡出，以及火灭后反而变重的型腔。在纸面上，浅色依靠饱和度和更深的物理底色来呈现（第 7 节，以及 `webgl.md` 第 8 节）。
- **凭眼睛修一处特写。** 调一个画家顺序的键，或挪一个航点，直到某一张截图看起来对，这会破坏另一帧或另一个主题。Raptor 手工设置的键在 1× 下看起来没问题，却有 323 个深度顺序问题。先测量（第 8 节"间隙与交叉"），再看。

## 3. 零件词汇与配方

`P` 是投影，`k` 是工具库（kit），如 `import * as k from "./iso-kit"` 所示。高度使用世界单位，z 轴向上。按列出的顺序绘制每个配方的实体。

### 带支脚的底座
```js
const PLATE = { x: -128, y: -64, w: 262, d: 128, r: 8 };
halo:  `<path class="iso-halo" d="${k.haloOf(PLATE, -17, 12, P)}"/>`
feet:  for (const [x, y] of byDepth(k.corners(PLATE, 22))) {
         k.cylinder(x, y, 7, -17, 1.6, P, 28)            // flange, tone lo
         k.cylinder(x, y, 5.4, -15.4, 3.4, P, 28)        // foot, tone mid
       }
slab:  k.slabOf(PLATE, -12, 12, P, 8, 1.6)                // tone mid, bevel 1.6
groove: k.planOutline(k.insetPlan(PLATE, 5), 0, P)         // line lo
screws: k.corners(PLATE, 10) → k.ring(x, y, 2.2, 0, P, 16) (line lo) + dots size .5
```
用以下方式对支脚排序：`byDepth = (pts) => [...pts].sort((a, b) => k.depthOf([a[0], a[1], 0], P) - k.depthOf([b[0], b[1], 0], P))`。

### 标尺条与铭牌
```js
const strip = { x: -110, y: PLATE.y + PLATE.d - 15, w: 230, d: 7, r: 1 };
k.slabOf(strip, 0, 0.6, P, 3)                                   // tone lo, crease none
const t = k.topTicks(strip.x + 4, strip.x + strip.w - 4, 4, 5, strip.y + 0.8, 0.6, [2, 3.6], P);
t.minor → line lo, t.major → line mid
label plate: k.slabOf(plan, 0, 0.8, P, 4) + k.planOutline(k.insetPlan(plan, 1.6), 0.8, P) (faint)
             + three k.lineOnTop rule lines of different lengths (lo, { free: true }) + two screw dots
```
刻度只存在于标尺条或表盘面上，并扎根于其边缘：`topTicks` 让每个刻度从 `edge` 生长出来，所以把 `edge` 放在条的边缘上（或距其 1 单位以内）；`sideTicks` 则把它们从 `top` 悬挂下来，所以传入面的顶边，而不是低于它 2 单位。裸板上的一排记号，是一种两端都悬空的纹理。铭牌上的细线代表印刷文字，所以它们是唯一允许线条停在裸面上的地方：传入 `free: true`，让线端检查知道这是有意的。

### 箱体上的接缝、焊缝与装饰线
```js
const seam = k.sideSeam(TANK, 14, P, 6);                         // visible near half of the plan at z = 14, round the corners
k.solidSvg(k.slabOf(TANK, 6, 98, P, 6, 1.2), { tone: "mid", inner: k.lineSvg(seam, { tone: "faint" }) })
```
箱体上的接缝、焊珠、包边或盖缝线绕过可见的圆角，并准确结束在垂直的轮廓边上，就像圆柱上的 `sideArc`。传入板自身的 `steps`，让接缝跟随相同的刻面；并把它作为 `inner` 传入，让它的端点位于轮廓线之下。只属于一个面的线（加强筋、面板接缝）贯通整个面、从一条边到另一条边：`segment([x, y, z0], [x, y, z1])`，其中 `z0` 和 `z1` 分别是面的底与顶，绝不是 `z0 + 3`。槽口与通风口是闭合轮廓（一个细长圆角平面图的 `planOutline`，或在面平面内同样的东西），所以它们根本没有端点。绝不要把线从角上内缩几个单位：在 4× 下它读起来像一个中断的纹理。

### 从密封座伸出的杆
一根活塞杆、一个柱塞或一个滑块，只要其可见长度随移动而变化，就是一根杆：一次按全长（可见部分加行程）构建，位于密封座内的部分被裁掉：
```js
const ROD = G.rodOut(F, gland, tip, r, P, { stroke });           // F.a points out of the gland
svg = `<clipPath id="rod"><path data-hold d="${ROD.clip}"/></clipPath><g clip-path="url(#rod)">${k.solidSvg(ROD.paths, { lit: true })}</g>`
R.put({ ..., move: G.mul3(F.a, stroke), svg, shapes: [R.solid(A.slide(F, gland, tip, r, { name: "rod" }))] })
live: el.setAttribute("transform", `translate(${dx} ${dy})`); holdStill(el, [dx, dy])   // dx, dy: the item's screen offset this frame
```
`rodOut` 返回杆从 `gland − stroke` 到 `tip` 的路径，以及一个从密封座面覆盖到 `tip + stroke` 的裁剪区。裁剪路径带有 `data-hold`；任何移动该条目的代码都以相同的屏幕偏移调用 `holdStill(el, [dx, dy])`，它会让裁剪区反向移动，于是密封座面保持不动，而杆从中滑过。当条目反向移动时，同一个辅助函数把杆收回密封座（加载缸）。在密封座上画一个淡色的密封圈（密封座面上的 `circleOf`，半径 `r + 0.4`）。用 `A.slide` 记录它——审计通过从密封座面拉伸杆（而非平移）来摆姿势，于是间隙、深度与实体检查在每一帧看到的都是真实的杆。绝不要用重叠的复制品伪装伸出：每个复制品的受光边缘停在下一个复制品的填充开始处，轮廓在移动时每隔几个单位就被啃出缺口。

### 立柱、轴环、卡箍与翼形螺钉


### 带指针的滚花旋钮
```js
k.cylinder(cx, cy, 6, z, 4, P, 32)                          // mid
k.knurl(cx, cy, 6, z, z + 4, 36, P)                         // line lo
k.lineOnTop([cx - 3, cy], [cx + 4.6, cy], z + 4, P)         // pointer, line hi
```

### 套在杆上的螺旋弹簧（为画家顺序拆分）
```js
const c = k.coil(xFrom, xTo, [rodY, rodZ], 4.2, 6, "x", P);
c.back  → line lo, drawn BEFORE the rod
rod     → k.slabOf({ x, y: rodY - 2, w, d: 4, r: 1.8 }, rodZ - 2, 4, P, 3)
c.front → line mid, drawn AFTER the rod
```
弹簧压缩时每帧重建它，只需改变 `xFrom`/`xTo`。这很便宜。

### 百分表（表面朝上）


### 灯、探头与手指
它们是圆柱的堆叠：外壳、盖圈、轴环、杆、垫。接缝圈来自 `sideArc`，锁紧螺钉是侧面的一个小板加一个圆柱头。

## 4. 色调

| 元素 | 色调 |
|---|---|
| 底座、支脚、地板 | `lo` |
| 结构：立柱、导轨、框架、滑架、箱体 | `mid` |
| 主体：被讲解的东西 | `hi` |
| 读者此刻应当关注的部分 | `lit`（仅限一处） |
| 凹槽、内缩轮廓、地板网格 | `faint` |
| 次刻度 | `lo` |
| 主刻度 | `mid` |
| 零位标记、指针线 | `hi` |
| 螺钉与铆钉 | 0.4–0.55 的 `mid` 圆点 |
| 折缝（顶/侧交接） | `faint`（默认），hi 零件上用 `lo` |

带 `lit` 的 `Solid` 会得到白色边缘和更亮的顶面。把它用于运动的主体、柱塞或被选中的抽屉。

## 5. 画家顺序（由后向前绘制）

- 先画底座，再画架上它的一切。
- 同一层级内，按 `depthOf(centre, P)` 升序排序：远的先画，近的后画。
- **拆分包裹类零件。** 对于环绕滑架的弹簧或框架，先后半、再内部件、再前半。在测试台上：后框架杆 → 带后半弹簧圈的杆 → 滑架 → 玻璃 → 前半弹簧圈 → 前框架杆 → 表盘。
- **运动零件**按其在顺序中的位置绘制，放在移动它们的 `<g transform>` 内部。如果一个运动零件可能一会儿在同一个邻居前面、一会儿在它后面，就拆分这个邻居，或限制运动范围，使顺序永不改变。
- **立在阶梯表面上的东西。** 安排台阶的顺序，让较高的在后面。这样，放在较低台阶上的探头就不会被前方较高的台阶挡住。
- 穿过水平零件的竖直零件（穿过卡箍的立柱）分两段绘制：水平件的下方与上方。
- **裁剪口就是一条边。** 在裁剪把一个零件对着另一个零件结束的地方（进入其链环的拖链段、密封座处的杆），让裁剪截面与接合面齐平，并沿切口画一条随裁剪一起移动的描边边缘（`data-clip`）。在等离子切割机上，有一段拖链的裁剪截面伸过了接合面。该段的顶面与槽口杆被画进了链环空腔 26 单位，结束在一个没有描边的垂直切口上——这就是一条半途而废的线。重排画家顺序的键也修不好它：链环的端面确实位于该段之后。
- **密集图示的键由几何决定。** 超过几十个相互重叠的零件后，手工设置的偏置会互相打架。给每个条目它的真实形状，让 `kit/audit.mjs` 在两个条目重叠处测量哪个面更近，然后 `orderKeys` 把每个键抬高到刚好满足每一对的程度（`kit.md` 第 12 节）。它无法满足的是互相咬合的一对，那需要拆分。第一版 Raptor 手工设置的键留下了 190 对组装态画反了的配对和 133 对分解态画反了的配对；测量出的键把两者都降到了零。
- **交叉按管段排序。** 管件或线缆画成 `tubePieces` 管段，每段都是位于自身深度的独立条目，于是一条线可以在一个零件前面、在下一个零件后面穿过。两条线在屏幕上交叉的地方，离相机更近的管段后画；只有当一个管段没有在别处也跑到另一个后面时，这个交叉才可排序，所以在交叉处断开长管段（`breaks`）。

## 6. 相机与构图

- 默认相机：方位角 45°，仰角 30°。旋转方位角（35–60°），让承载机构的那一面朝向观众。测试台用 57° 来展示长边。想看清敞口内部时抬高仰角：波纹槽用 44°，让水面与槽下的纸面都清晰可读。
- 用 `fitProjection(boxCorners(...) ∪ tallest points, width, height, { pad: 24–34, azimuth })` 适配。典型的 viewBox 是 600 × 340–380。
- 物体约占卡片的 55–65%。四周留白，别让它碰到角标，并保持一组图示之间尺寸一致。
- 在手机（390 px）上，确认它依然清晰可读。如果零件变得太小，就在一个带 `overflow: hidden` 和负外边距的卡片内，把 SVG 放大到约 110–118%，正如测试台示例中 `stretch.css` 所做的那样。

## 7. 主题

`ISO_CSS` 在 `.iso` 上定义令牌，默认为深色，`.iso[data-theme="light"]` 为浅色。每个填充与描边都读取令牌，所以一个主题就是一套令牌。要调整一个主题：

- **纸面**（`--anatomy-paper`）等于卡片颜色，于是填充能遮住背后的东西，而又不显出色块。
- **色阶。** 四档，从最暗（0，背光面）到最亮（3）。让它们接近：亮度相差约 3%。
- **线条。** 深色模式下，`hi` 接近白色，`faint` 仅略高于纸面。浅色模式则相反。
- **光晕。** 底座下模糊的深色填充：深色模式下浓，浅色下约 30%。

**浅色优先发布。** 等轴测网站上的每个图示都是浅色的，其着色器也不例外。先设计浅色，并让深色在成本低廉的地方保持可用。七次着色器改造在绘图方面带来的教训：
- **每个颜色都是令牌。** 一个直接敲进图示 CSS 或其着色器的颜色，就是一颗等着爆发的主题 bug。给它一个浅色值和一个深色覆盖值（`.x { --x: … }`，然后 `.iso[data-theme="dark"] .x { --x: … }`）。着色器需要同一颜色的地方，从令牌读取（`webgl.md` 第 8.3 节）。
- **型腔要有自己的令牌集。** 炉口内部、浇包、剖切看到的容器内部、水柱或管道观察窗的内部之所以更深，是有原因的：烟灰、耐火材料、深度、阴影。给它的组一个类，把 `--anatomy-paper`、`--anatomy-face`、`--anatomy-top`、四档色阶和线条色调重定义为更深、更暖或更偏蓝的灰。保留全部色调，让它仍然有形体；用实时代码写入的变量把它朝光源的色相混合；在深色下把令牌设为 `inherit`。这样辉光有了落地的底色，而又不是一个黑盒子。
- **当心嵌套主题。** 深色底板可能坐在浅色页面上。写成 `.iso:not([data-theme="dark"]) .x` 的规则也会透过周围的页面匹配到东西。把深色规则排在浅色规则之后，或者以底板自身的主题为准。
- **透明度会让淡色褪成灰色。** 任何在浅色下靠透明度淡出的东西（回退辉光、点亮的高光）都要给一个饱和的令牌，并且它的淡色要正片叠底混合，让底下的线条依然可见。

## 8. 回转零件与管件

发动机、泵、阀门、灯具和仪表大多是回转零件与管件。`kit/lathe.mjs` 与 `kit/tube.mjs` 沿任意轴构建它们（`references/kit.md` 第 10、11 节）。`examples-raptor-engine/build.mjs` 以可运行的形式包含下面的每个配方。

### 回转零件：按经线思考
把一个零件写成它的半截面：一串从一端到另一端的 `[s, r]`，然后用 `G.solidOf(profile, F, P)` 把它车削成体。
- **台阶与肩部**是半径在同一个 `s` 处跳变的地方：`[6, 12], [6, 9]`。它们形成读起来像机加工的折缝线。
- **曲线**是许多标记为平滑的点（`[s, r, 1]`），于是不会在它们上面画出折缝：钟形、穹顶、汇入法兰的圆角。工具库会自动平滑地给任何带平滑顶点的型面上色（`smooth: "auto"`），于是着色跟着曲线走，而不是一个刻面一个刻面地跳；只有想退出时才传 `smooth: false`。
- **收腰的形体绝不做凸包。** 中间收窄的型面（喉部、线轴）有凹轮廓。`lathe` 会在其真实轮廓沉入其环的凸包超过半个像素时发现这一点，然后改用轮廓与可见端弧来填充和描边（`fill: "auto"`，或强制 `"surface"`）。按凸包绘制时，Raptor 的喉部是一个直锥，带着一条苍白的未着色带和一条离轮廓还差 8 px 就断掉的接缝。
- **曲面上的接缝与焊缝**是 `G.arcOf(F, s, r, P, { slope })`，采用该环处型面的斜率，画成 `faint` 并作为实体的 `inner` 传入（`solidSvg(paths, { inner: lineSvg(arcOf(…), { tone: "faint" }) })`；Raptor 的 `S` 与 `Ln` 是它们的一行包装），于是它们位于轮廓之下。它们准确结束在边缘处，或差一点点。接在实体之后拼接时，每条接缝的圆头会落在边缘描边上，Raptor 作动缸的深色主题轮廓在 4× 下看起来是虚线。
- **长形体**（喷管、炮管）用 `G.bandsOf(profile, cuts, F, P, { radius, slope })` 切成若干环带，于是每个环带都能与缠绕它的管件做深度排序。这些环带共享同一套 `steps`、同一个法线场和同一个面，各自的轮廓被清除，`sidesOf` 为整个形体画一条连续轮廓（`kit.md` 第 10 节），于是色调曲线无台阶地穿过每个接合部，侧面也不会打弯。没有解析的 `radius` 与 `slope` 时，它会对整个型面拟合一条曲线，而不是每环带一条。
- **环带上的环**（燃烧室上的加强环、轴环）要把环带拆开：环带、环、环带。画成一条长环带再把环放上去，环的后半会盖住环带（或环带挡住环的前半）；拆开后，每一块自己排序。Raptor 的燃烧室外套是其两个环之间的三段环带。
- **开口端**是一个 `ringBand` 唇口，带一个填充的暗区（`circleOf`）表示黑暗的内部，内弧来自 `arcOf(..., { inward: true, least: -1 })`。螺栓点围在唇口周围。

### 回转体上的零件
- **法兰：** 背面贴在路径端点上，于是路径准确结束在安装座表面上，圆盘从那里沿管件往回延伸（`centre = end − tangent · t/2`）。`disc(-t/2, t/2, r, frameAlong(centre, axis), P)`，在朝向观众的那个面上放一圈螺栓 `dotsOf(F, faceS, 0.74r, 8, P, { all: true })`。当面侧向对着观众时（`|dot(a, V)| < 0.12`）省去螺栓。
- **曲面壁上的凸台或接口：** 沿外法线方向的短 `disc`，朝向观众时带一个 `faint` 面环（`circleOf`）。敏感管、点火器或插塞就落在这里。让它至少和落在它上面的法兰一样宽；悬在凸台之外的法兰会在边缘浮起来。
- **鞍座垫。** 回转体上的平法兰会在边缘留下间隙（拱高，`R − √(R² − a²)`）：18.4 的泵体上放 11.6 的法兰，两侧会离 4 单位。只要这个间隙可能超过约 0.15，就把法兰坐在垫块上：一个底面贴合宿主表面的短圆柱（`G.saddleOf(F, a, start, h, P)`，其中 `start(angle)` 由宿主的形状决定，即 Raptor 的 `padOn`/`boss(..., { host })`）。把它记录为被宿主 `cut` 的圆盘并标记 `seated`，让审计看到它的真实形状。让垫块保持在宿主的一段环带内（沉到台阶下的悬伸会画在挡住它的环带前面；一块 Raptor 垫块降到位到接触下面的台阶后，每一帧都成了咬合）并避开宿主的轮廓：跨在轮廓上的垫块一半在宿主前一半在宿主后，没有画家顺序能画它。Raptor 的 LOX 导管为此从 130° 挪到了 150°。**鞍座属于其宿主的装配体。** 它的底面按宿主的曲线切割，所以如果它跟着管件飞走，分解态下切割的底面就会暴露：Raptor 的热气垫块按甲烷泵的涡轮与环切割，分解后成了带尖尾的锯齿碎片。把垫块交给宿主的部件（`boss("ftp", …, { host: FTP_TURBINE })`），让运动管件的法兰只离开它的平顶面；审计的 `seats` 会列出每个宿主随另一个装配体运动的 seated 形状。
- **点火器插塞，一个终端。** 一个插塞要么引点火线（沿其轴从外表面引出），要么引激励线缆，绝不两者都引。线缆落在它旁边自己的小凸台上。
- **管件上的阀门：** 在 `frameAlong(point, tangent)` 上用一个鼓胀的 `lathe` 型面，以 `smooth: true` 车削，两端面上有螺栓点，一个圆形颈和一个带盖轮廓与两颗螺钉的作动器箱。它坐在一段直腿（本体长度加两处圆角切口）上，管件在其本体下方断开缺口，作动器与管件垂直：水平管上朝上，竖直管上朝侧（一个圆罐），绝不顺着管件。
- **蜗壳：** 把 `spiral(F, s, r0, r1, a0, a1)` 连同沿程渐增的半径喂给 `tubePieces`。让它的中心线保持在壳体半径加管半径加 0.3，于是它相切地缠绕壳体；沉进壳体的蜗壳就是穿过实体的管。
- **球接头与三通**是球（`sphereOf`）：作动器上的杆端轴承，支管与歧管相接的铸造三通。
- **倾斜轴上的滚花、筋与翅片：** `ribsOf`。面上的叶片：带 `sweep` 的 `spokesOf`。

### 管件
- 把路径布成几个真实接口之间的直段，然后用约 2.6 倍管半径的弯头 `fillet` 它。管件会弯折，不会打结。
- 每根管件要么结束在带法兰的接口上，要么结束在带终端点的基座上。停在空中的管件，就是一条停在空中的线。
- 加上真实管线该有的零件：被夹住或焊住处的环带（`bands: [0.5]`）、需要弯曲处的波纹管（一串薄的 `disc`，`bellows: [from, to, count]`），以及控制流量处的阀门。这些是 Raptor `pipe()` 辅助函数的选项（`kit.md` 第 11 节）。
- 少用几种规格，每一种都大到能区分：主管道（r 5–8）、供给管（r 2–4）、敏感管（r 0.9–1.5）、线缆（r 0.5–0.65）。

### 选择航点
先布大管线（管道、下降管、歧管），再布供给管，然后敏感管，最后线缆，于是每条更小的线都绕开已有的东西。对每条路径：
- **从接口的法线出发。** 第一段沿表面法线直直地离开接口，长到够放法兰，然后转弯：`fillet` 最多吃掉较短一段的 0.48，所以短于约两倍弯半径的段会给出急弯，而正对观众的接口立刻转弯会掐扁（"间隙与交叉"，第 5 步）。
- **顺着结构走。** 线段与它贴附的形体平行（沿燃烧室、上下降管）或以固定半径绕它走一个环（`arcPoints`），与其外壳的间距用形体自身的间隙：外壳半径加约 1.5 倍线的半径。负责人的特写显示敏感管扇形掠过燃烧室表面、越过主管道去够它们的基座；在新版上，从喷管歧管引出的长线沿左侧上行，燃油阀线缆沿下降管旁上行，线束从控制器平行落下，进入被夹住的线槽。
- **待在主体自己这一侧。** 服务于远侧接口的线绕到背后，或沿一个环绕到侧面，绝不斜穿被讲解物体的正面。
- **优先横向过屏的段。** 正对或背对观众伸出的段投影很短，使它两端的每个转弯都成尖点或 V 形（"间隙与交叉"，第 4、5 步）。
- **给附件留地方。** 阀门、波纹管或卡箍需要一段直腿，至少为其本体加两处弯折余量（各处 `r_bend · tan(turn / 2)`）。在弯段上，直的本体会切进管件；Raptor 的下降管为此改了走向，让阀门坐在一段直管上，氧气管也为阀门让出了一段竖直直管。
- **不要落在杆上。** 管件的最后一段不能在屏幕上贴着杆、拉杆、立柱或导轨走，它的端部附件也不能压在某个的轮廓上：盲测台的软管最后一段与一根拉杆平行，高出 2 px，于是拉杆读起来像插进了软管接头。从杆的上方接近接口，或者转一下弯头，让这段横过屏幕。审计的 `crowding` 把每个细长实体（长度超过其半径或半宽的 4 倍）都当成线，所以它会让这些情况失败。每个姿态也要查：行程末端坐在运动板边缘上的套圈，读起来像碰到了板。
- **有意地交叉。** 如果两条线必须在屏幕上交叉，就交叉一次，在直段上，成清晰的角度，且深度上相距足够远，让间隙检查有富余地通过。靠近弯处或端部的交叉读起来像一个接头（"间隙与交叉"，第 6 步）。
- **拆分，不要重叠。** 在有东西包住管件的地方（法兰、环带、波纹盘、卡箍、阀体），管件在那里断开缺口，每一端各有一段结束在每个面上（`tubePieces` 的 `gaps`，卡箍用 `crossingsOf`）。用一个整段穿过去，管件就同时在这个轴环的后面和前面，没有键能排序它。Raptor 燃烧室外套正是因此在两个环处被拆开。

### 接触与接合
两个零件相遇的每一处，要么是平面对平面，要么是相切接触，要么是边缘落在回转体上。没有东西嵌进任何东西：嵌入的零件同时在其宿主的前面和后面，没有画家顺序能画它。
- **齐平。** 杆结束在叉头的面上；凸台从它立着的表面开始；耳座是从外壳到球的一根短销。
- **边缘落在回转体上。** 半径 `a` 的圆柱与半径 `R` 的球或管相遇时，结束在其边缘贴合表面之处，距中心 `sqrt(R² − a²)`。它的端面随后藏在宿主内部，什么都不会露出来。Raptor 的作动杆就是这样接上球接头的，歧管与下降管也是这样接上三通的。
- **三通。** 支管接入主管是一个略大于两者的球：主管在其边缘与球相接处断开缺口，支管结束在球上。球的大小要让两根管的边缘都不插进对方：半径 `b` 的支管接入半径 `a` 的主管时，`R ≥ sqrt(a² + b²)`。
- **支柱。** 为了接触曲面而不得不嵌入的环（绕钟形的歧管）靠小的径向垫块撑起，间隙至少为管半径的一半。
- **阀门与波纹管放直段上。** 弯管上的直车削体会在两端切进管件。把它们放在路径整段都是直的地方。
- **两个法兰，一个接合。** 管道螺栓连接到泵出口法兰的地方，管道自己的法兰与出口法兰面对面相接；同一处的两个法兰会咬合。这样图示分解时每个部件都各自留着一个法兰。
- **支管有接头。** 支管从三通离开主管（主管在其下方断开缺口，支管开始于其边缘与球相接处），或从主管上的鞍座垫离开，绝不从主管外壳的裸点离开。
- **撑杆终结于球接头。** 沿斜轴放置的撑杆眼片会嵌进它接触的东西。给每端一小段沿宿主法线的茎，茎上一个球，球之间是杆（四个接头处都是边缘贴球）。
- **运动接头用带平台的球。** 在 3D 图示中，落在球上的边缘不可能在每个角度都可排序。给球一个平台（`T.ball({ flats: [{ n, d }] })`，记录为 `A.ball(c, r, { flats })`），让边缘落在平台上，或者用同轴的关节盘。`references/3d.md` 第 5 节。
- **一切都被固定。** 每个实体都通过接触连接到基座：支架托着箱体，螺柱托着线束卡箍，齿轮箱板把电机连到作动器。只接触它夹持的线缆的卡箍是浮着的。

### 间隙与交叉
管件的中心线与除自身连接外的一切保持约 1.5 倍半径的间距，于是 0.6 的线缆与管道外壳留 0.3 的净空，管道与相邻者留半个半径。两条线必须在屏幕上交叉的地方，它们在深度上交叉，一个远远在前，由管段的键排序；管件穿过轴环、卡箍或阀门的地方，它在那里断开缺口（`kit.md` 第 11 节）。要证明它，而不是靠目测：
1. 构建时为每个条目和每根管录制一个形状，汇入同一个 `A.recorder(P, { order, spring })`（`kit.md` 第 12 节）：绘制条目连同其 `shapes` 用 `R.put`，每个形状用 `R.solid`，每根管件和线缆用 `R.route`。让辅助函数来做，这样什么都跑不掉。工具库画的每样东西都有录制的形状：地板棱柱用 `A.slab`、`A.extruded` 和 `A.cylinder`，回转零件用 `A.solid`、`A.lathe` 和 `A.disc`（沿绘图使用的同一条曲线描摹），`prismOf` 用 `A.prism`，球用 `A.ball`，管件也有。
2. 每次构建都用 `A.settle(R, P)` 定下画家顺序的键：它测量图示静止的每个状态（组装态与分解态）以及真实分解动画每一帧（`explodeStates` 回放活动弹簧与错峰）中的重叠，并运行 `orderKeys`。
3. 以 `A.auditOrExit(R, P)` 结束构建，并运行 `node build.mjs --audit`，直到每条失败行都归零。咬合的一对是几何 bug（拆分、留缺口或相切接触能修好它）；不要用偏置把它推开。
4. 线不能在屏幕上折返。离观众而去的水平段读起来像在上升，于是一条远去又下折的管读起来像个尖点、一根断在半空的管。先把段往屏幕侧面引（审计的 `folds` 找出每一种情况：4 倍半径内出现超过 140° 的屏幕转角，而真实转角不到 110°）。
5. 轮廓不能自折，弯处不能在屏幕上掐成一个点。一段先指向观众再转弯（从外套凸台径向伸出再爬向基座的敏感管、从传感器探尖绕回的发夹管）会把圆角边投影成侧视，两条腿成一个没有可见半径的 V。`folds` 测量每个超过 90° 的可见弯的屏幕半径，当它小于两倍管件的屏幕半径时判失败。修复方法，按优先顺序：让转弯发生在接头内部（凸台上的球三通，线从它离开奔向下一个点：即 Raptor 的 `elbow`，用于 sense0、sense2、sense5 和富燃料点火线）；在朝向观众的平面内弯折（Raptor 的发夹管在传感器自身的径向平面内回环，该平面正对相机；其本地辅助函数 `sideOn(d) = unit3(cross3(unit3(V − d·(V·d)), d))`，其中 `V = G.viewOf(P)`，给出沿 `d` 的一段的屏幕横向方向，于是在 `d` 与 `sideOn(d)` 平面内的弯朝向观众）；把接口挪到其法线横过屏幕的位置。法线与视线夹角满足 `f = |n·V|` 的平面内的弯，投影出的屏幕半径约为 `R·f²`；一旦它小于管件的屏幕半宽，单管段的内缘就会倒退，轮廓会自我交叉成一个小结（审计的 `selfOverlaps`）。`fillet(…, { P, tube })` 会抬高每个角的半径来避开这点，但只能抬到腿允许的程度，所以给接口旁的转弯至少 `R + 3r` 的直腿。正对观众开口的接口（Raptor 甲烷泵上的测速探头）会让每种接近方式都成发夹弯：挪开它。
6. 交叉发生在直段上，清晰明确。一条线的弯处或端部在屏幕上落到另一条线的轮廓上（接触，或重叠任何程度），眼睛就会读成一个接头或一条穿进另一条的线，无论真实深度如何：从敏感管弯头后面探出的发夹钩、分解态落在另一条线环带上的法兰、在屏幕上贴着一段短管并越过其端法兰的线缆。接头也算：线束卡箍的轮廓落到另一条线上，会读成那条线从卡箍里长出来，Raptor 的卡箍在氧到预燃室管线上分解时就出了这事。审计的 `crowding` 列出每个可见的情形，组装态与分解态都列；改一条线的走向，让相遇成为两条直段的清晰交叉，或至少一像素的可见间隙（卡箍为两像素）。只有在你用 8× 看过之后，才能豁免一对（`CROWD_OK`）。

第一版 Raptor 有 54 个间隙问题（39 个穿件）和 323 个深度顺序问题；本节的路由规则把两者都降到了零。

### 曲面上的着色与纹理
- 每个曲面都要**平滑着色**（任何带平滑节点的型面自动启用；解析曲线用 `smooth: { slope }` 或 `{ slope, radius }`；分段形体用 `bandsOf`；球用 `sphereOf`）：钟形、喉部、穹顶、锥体、阀体的鼓胀、球。每行一个平面刻面色调只对圆柱是对的。只要区域数量撑得住，每个色调就是覆盖整个形体的一个多边形，于是看不到行的接缝。
- **纹理结束在边上或淡出，沿轴方向也一样。** 每根筋的 `s0` 与 `s1` 准确落在同一个 `s` 处画出的台阶、折缝或接缝弧上：传 `seams: true`，`ribsOf` 会连同筋一起返回两条接缝弧，这样它们就不会各自漂移（盲测电机的筋从 26 做到 88，接缝在 24 和 90，结果每根筋两端都短了 2 单位）。筋排所在处没有接缝时，让它跑到结束该环带的面上（`s0`、`s1` 等于环带的两端）或让它淡出。
- **管件上的纹理跟随其截面。** 编织、波纹、缠带与护甲来自 `tubePieces(route, r, P, { rings: { pitch, twist, cross, fade } })`：环（带 `twist` 时为螺旋，带 `cross: true` 时为双手编织）按整条路径的 3D 弧长放置，每个都画成其截面的可见前弧，向两侧边缘淡出，结束在套圈与缺口面上。绝不要沿管段中心线用 `stroke-dasharray`：它会沿软管以笔直生硬的边结束，不贴合圆截面，在弯的内侧堆积，并在每个管段接头处重新开始。
- **纹理结束在边上或淡出。** 只画朝向观众那一侧的筋与螺栓圈会停在截断落下的地方，即表面中间：Raptor 燃烧室环上的螺栓圈在负责人的特写里就是这样。用 `ribsOf(..., { fade })` 配 `fadedSvg`、`dotsOf(..., { fade })`，让它们朝转弯处淡出（Raptor 螺栓点用 `fade: [0.04, 0.42]`，筋用 `[0.1, 0.55]`）。接缝弧与环带线本来就结束在轮廓上。一条必须在面中间停住的纹理线（到头没了的凹槽、差一点没到角的焊珠）用 `fadeLineSvg(points, { fade: [start, end] })` 绘制，它通过沿线的渐变在几个 px 内逐步淡出；绝不让它结束在光秃秃的切口上。截断位置要按特征的朝向来选，而不是按它坐在哪个环上来选：倾泻环顶部的喷孔朝上，四周都看得见，所以它们用 `all: true`。被环的外法线剔除（`least: -0.2`）后，Raptor 的那一排就在刚过环侧面处以全强度停下，而环继续绕到背后，光秃秃的。绝不要用径向 `least` 去截断朝上特征上的一排；如果它真的有一部分被挡住，就朝转弯 `fade`。
- **平滑的色调会收窄。** 色调带沿曲面型面出现或消失的地方，它从零宽度诞生再长宽（`smooth` 按屏幕误差细分行，直到每条边界都在 0.35 px 以内，且每次色带数量的变化都发生在一个薄条里）。一条结束在横过表面的直切口上的色带，或一块苍白的裸露填充楔形，是评审者最先发现的 bug。
- **形状与着色描述同一条曲线。** 型面的平滑段用单调三次 Hermite 曲线（Fritsch–Carlson）插值，工具库对法线、色调片、轮廓与凸包都使用同一条曲线。自然样条会在峰附近过冲：在 Raptor 的阀门上，它给一个只升一次降一次的形体塞进了三处斜率变号，色调带像木纹一样在鼓胀处 zig-zag，而轮廓保持为一条多段线，每个型面点都有一个小疙瘩。单调曲线只可能在型面转弯的地方转弯。
- **单调 Hermite 只有 C1。** 它的 `dr/ds` 是分段二次的：节点是手打的时候，它在每个节点处走平、在节点之间过冲，而跟随斜率的色调带会停滞然后猛冲，形成扇贝状的阶梯。Raptor 的喉部在一个只朝一个方向弯的型面上有五处斜率极值；它的甲板锥抖得轻一些。任何大于接头的弯曲形体都需要解析型面 `r(s)` 及其导数，作为 `smooth: { slope }` 传入，在 20–30 个节点上采样：喉部是 `√(24.2² + (c·(s − 146))²)`，锥是 `48·(1 − x)^0.8`，在其尖端以竖直切线闭合到 `r = 0`，于是轮廓在尖端圆滑过渡，而不是在平的端盘上方耸起。审计的 `wobble` 会让任何没有 `slope` 却被平滑、且其 `dr/ds` 在两端之间转向的型面失败。
- **轮廓是椭圆，不是刻面多段线。** 刻面数只用于色调填充（屏幕上每个刻面约 3 px，`stepsFor(r, 32, 160, scale)`）；每个轮廓、边缘与折缝都以约 1.5 px 从解析圆采样，折缝与倒角准确结束在面转开的地方。20 边的法兰轮廓挨着 96 采样的圆环，在 4× 下读起来像一个缺口。
- **管面条纹。** 明暗带连续穿过管段接头并一直画到底：在每个封口端，它们跟随端椭圆的外半；在朝向你的端面上，它们停在它的内缘上，而内缘是画出来的。在接头处，条纹比本体多伸出 0.5（本体重叠 0.5，条纹重叠 1），且每一帧都从整条路径计算，于是后一段的条纹盖住自己本体的抗锯齿切口，并结束在一条相同的条纹上。本体与条纹按同一条线裁切时，每个接头都有一根发丝线横过蜗壳的暗带，浅色主题下发亮、深色主题下发暗。在每个弯、三通、波纹管和法兰处、以及在强烈弯曲的锥形管上，用 4× 检查它们。你自己在管段上画的任何东西（纹理、流动痕迹）遵循同样的规则：从整条路径计算，按离路径起点的 3D 弧长定相位，并延伸到管段的条纹悬伸之外（每个接头外 1 单位），否则接头会显示成半截虚线、重影或缺口。`rings` 选项会替你做这些。

### 线束布线
线缆是毁掉一个图示最简单的办法：横过主体正面画的线缆读起来像涂鸦。像真实的线束一样布它们：
- **线槽。** 让线缆在绕形体的一环上并行成槽（`arcPoints` 固定在某个 `s`，每条槽向外偏 1.4 单位、沿线偏 0.2 单位，适用于 r 0.62 的线缆）。它们只在分支去插头时才离开线槽。
- **有序进入。** 线缆从连接器平行落下，在落点与线槽相接处接入环（`acos(x / laneR)` 处），于是最内侧的槽由最靠前的连接器供线，没有落线会交叉。
- **有序离开。** 最外侧的槽最先离开环；内侧线缆在外侧线槽还在旁边走的时候转向外，就不得不穿过它们。
- **顺着结构走。** 需要爬升的线缆贴着管件上行（Raptor 的阀线沿下降管上行），而不是穿过发动机前方的空档。
- **短分支。** 从线槽直奔接口。不要斜穿主体的正面。
- **卡箍**（`disc(-0.9, 0.9, r, frameAlong(point, tangent))`，色调 `mid`）按规律的角度把线槽固定在形体上。每根线缆穿过卡箍处断开缺口（`crossingsOf`），否则卡箍与线缆会咬合。
- **端部着地。** 每根线缆起于控制器或接线盒上的连接器，结束于插头、传感器探尖、阀盖或舱壁连接器，绝不结束在卡箍上或线束旁的空气中。留在自己装配体里的端部得到一个终端点；在另一个装配体上的端部得到一个随线缆移动的连接器壳（`cable(..., { shells: [false, true] })`）。
- **数清你画的。** 把每条路径推进一个列表（`CABLES`），并按它的长度构建读数。第一版 Raptor 的读数声称 8 根线缆，实际画了 11 根。

## 9. 分解视图
当零件本身就是解释（什么喂什么、按什么顺序）时，分解视图才有存在的价值：
- 选择真实物件能拆成的装配体（Raptor 有 11 个），而不是单个实体。
- 沿每个装配体真实的拆装方向移动它，远到其轮廓能离开相邻者：堆叠的级沿轴向下，侧面的单元径向外移。
- 每个零件都有自己的归属。跨接两个装配体的零件（作动器、线缆）跟着它们保持连接的那个走，且分解时仍然结束在自己的东西上：法兰、快断处的连接螺母、线缆上的连接器壳。撑杆端是宿主上的球头螺柱，杆随其装配体离开，鞍座垫留在宿主上。标记分解时会脱离安装座的每个端（`free: [true, false]`）；审计的 `looseEnds` 会让分解态下没碰到任何他属零件的其他每个端失败，并列出自由的端，让每个都成为一个选择。
- 高亮与运动是分开的。螺栓固定在燃烧室上的传感器随管路一起高亮，但搭乘燃烧室的弹簧（`ride`，输出为 `data-ride`）。用另一个装配体的向量在它自己的弹簧上移动，它会沿安装座滑动，并在半途中沉进去。
- 选择分解向量与错峰，让任何一帧里都没有东西穿过任何东西：`references/motion.md`（"安排错峰，让任何东西都不必穿过别的东西"）有规则，审计会回放真实弹簧的每一帧——打开、关闭、中途反转——并在任何穿件时失败。
- 在图例中把装配体列成编号按钮（`01 Gimbal and thrust puck`…），点击即选中，与悬停相同。
- 弹簧、错峰与每帧深度重排在 `references/motion.md`。

## 10. 屏幕与面上的物件
屏幕、表盘面或显示屏画在它所坐落的那个面的平面内（`examples-desk-computer/`）：
- **面平面。** `sideMatrix([0, y], 0, P, "left")` 把一个组的局部 `(x, −z)` 坐标映射到 `y` 处的竖直面上。屏幕上的每样东西（辉光、扫描线、标记、`<text>` 和光标）都以那些平面坐标画在那个 `<g transform>` 内部。
- **凹槽。** 用同一平面内的 `clipPath` 把屏幕裁到它的圆角轮廓，并把凹槽的内侧面画成面与后退 `depth` 后的面之间的四边形。侧面按朝向着色（顶面 `iso-top`，侧面按色阶）。轮廓在面上画 `lo`，背面画 `faint`。
- **面上的运动**是面坐标里的变换。CRT 关机把画面绕屏幕中心缩成一条线，再缩成一个点，带一道电子束线和一个淡出的点。
- **机器显示的文本**（一行键入的文字、计数器的数字）是物体的一部分，不是标签，所以一标签规则不适用。用屏幕自己的字体和大小，并把它放得进去：字帽高度约为窗口高度的 0.55，你将要显示的最宽字符串（`8.88`，最长的单位）必须在宽度上放得进去，并留约十分之一高度的余量。像对待任何屏幕一样把它裁到窗口内。一个盲测流量计在 12.8 × 8 的窗口里放了 5.6 px 的数字，于是首位数字越过了窗口左边框，数字顶部撞上了单位标签。
- **透过开口看到的内容**（视镜、表窗、凹槽）位于面的后面，所以把开口的内壁画面与背平面之间、按朝向着色，并把内容同时裁到面平面内的开口和它自己的开口。开口内一条裸露的面读起来像画在表面上的一个洞。开口后面的着色器，见 `webgl.md` 第 5 节。

## 11. 着色器
有些主题没法用线条画：火、排气、水、焦散、真实的灯光、蒸汽。这些放进绘图*内部*的一个 WebGL 层，位于世界空间、同一个相机、背面 SVG 与正面 SVG 之间。`references/webgl.md` 有层栈、相机契约、工艺规则（不跳变、无硬截断、色调映射与抖动、按主题混合）以及如何验证它们。本页的一切仍然适用于效果周围的 SVG。它的第 8 节覆盖浅色主题，也就是要发布的主题：从纸面应呈现的颜色求解墨色、随光增强的墨色、每处辉光的深色物理底色、炽热金属、玻璃、火花、火焰、蒸汽、等离子体与切伦科夫光的配方，以及一个与着色器匹配的无 WebGL 回退。
